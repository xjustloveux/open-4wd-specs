# 零件參考圖

> **參考件（非 spec）**：本檔為圖像生成提示詞——術語 ／ 數值以本 repo canon 為準（[建模參數.md](../../建模參數.md)／ [程式架構/builtin-assets.md](../../程式架構/builtin-assets.md)）。

本文件提供 8 類部件 × 3 archetype（`speed / heavy / control`，對應公版設計方向，見 [程式架構/builtin-assets.md §5](../../程式架構/builtin-assets.md)）= 24 個公版提示詞 + 1 個 UGC 造型範例（8.4），用於 codex（或其他 AI 圖像生成）產出參考圖，再餵給 Tripo3D / Meshy / 等服務生成 GLB。

每個提示詞都已內嵌**兼容介面規格**（孔位、尺寸、安裝面），確保不同玩家自製的同類部件能彼此互換、不同類部件能正確組裝。

---

## 使用方式

1. 每個提示詞產出一張參考圖（PNG 建議 1024×1024）
2. 將圖丟給 Tripo3D（建議 50K 面 + 1024 紋理 + Quad output——**生成用高模**；出貨前必經減面／紋理優化，最終預算見 [程式架構/builtin-assets.md §7](../../程式架構/builtin-assets.md)：零件 ≤ 8K tri・≤ 112KiB〔超過原 100KiB 的額度僅供完整 PhysicsManifest／物理 metadata〕／場地 ≤ 500KiB）
3. 將生成 GLB 匯入 Stage 2 編輯器（或等效公版 authoring 管線）完成 decimate、材質、Mount / Empty 與 schema 編輯；Draco + KTX2 由 finalize 管線處理
4. Stage 3 嚴格檢核後依用途分流：公版進入 `assets/builtin/parts/<類別>/<檔名>.glb` 且不上鏈；UGC 可存為 `local:` 本機測試資產或上 IPFS + ledger

### 提示詞中尺寸的性質

提示詞中的「6mm 軸孔、24mm 馬達座、96mm 軸距、32mm 輪胎外徑」等數字預設是 **canonical 視覺引導值**；只有另列入介面表的 mount／hinge 配合特徵才是嚴格契約。它們的作用：

- **協助 AI 圖像生成**畫出合理比例的物件
- **協助 Tripo3D** 從圖中推斷適當的幾何尺寸
- **設定玩家對「標準件」的視覺期待**

實際裝配時，**真正決定相容性的是 mount empty 系統**（chassis 端 `Mount_*` slot 配對 part 端 mount：tire / roller 走前綴匹配、其餘嚴格相符，見 [零件與共用介面.md §6](../../建模參數/零件與共用介面.md#6-mount-結構表chassis--part-配對)），不是 mesh 上的視覺特徵尺寸。

Convert script 只對介面表列出的 feature 做 **逐特徵絕對公差**檢核（見 [零件與共用介面.md §7.3](../../建模參數/零件與共用介面.md#7-約束限制stage-1--stage-3-嚴格檢核)）：

- mount center、hinge axis／radius／width 與 mating normal 使用各自明列的 m／degree 公差；
- 公差內通過，超出即 Stage 3 拒收，不存在全零件共用的百分比軟警告帶；
- 輪徑、馬達總長、滾輪外徑、AABB 與外殼比例只作視覺／平衡參考，不得作 UGC 拒收門檻。

所以圖檔生成階段不需要 pixel-perfect 精準（AI 圖像生成本來也做不到），只需要視覺上看起來合理。後續的 mount empty 步驟才是真正保證裝配的環節。

## 標準兼容介面表（Standard Interface Contract）

所有同類部件**必須遵守**這張表。這是部件互換的「契約」。

| 介面 | 規格 | 出現在 |
|---|---|---|
| 車軸孔 | 直徑 6mm 貫穿 | tire（孔）、chassis（4 個對接孔）|
| 軸距 | 96mm（前後軸對) | chassis、body |
| 馬達座 | 圓杯凹陷直徑 24mm，深 12mm | chassis（凹）、motor（外殼匹配）|
| 馬達輸出軸 | 直徑 2mm，伸出 8mm | motor |
| 電池倉 | 矩形凹陷 60×30×14mm | chassis（凹）、battery（外形匹配）|
| 晶片倉 | 矩形凹陷 30×20×6mm | chassis（凹）、chip（外形匹配）|
| 車殼柱 | 4 根直徑 5mm，高 4mm，分佈四角 | chassis（凸柱）、body（孔對接）|
| 導輪螺絲座 | 直徑 2mm 螺絲孔，深 10mm | chassis（多個）、roller（中心孔）|
| 武器安裝面 | 12×8mm 平面 + 2 個 2mm 螺絲孔 | chassis 前保險桿、weapon 安裝面 |

整車目標尺寸：130mm（長）× 78mm（寬）× 50mm（含車殼高）。

## 共通渲染風格 prompt prefix

所有提示詞都應該以這段開頭：

```text
Photorealistic 3D product render, single isolated object centered in frame, 
plain light gray background (#dcdcdc), soft studio softbox lighting from 
above-front at 30-degree angle, gentle ambient occlusion at contact points, 
no harsh shadows, sharp focus on entire object, clean technical catalog 
photography style, neutral white balance, 3/4 front-elevated view at 
35-degree elevation looking down.

CRITICAL — image must contain ZERO annotations: no text of any kind, no 
labels, no callouts, no dimension lines, no measurement arrows, no 
position markers, no part numbers, no logos, no watermarks, no caption 
overlays, no schematic guides, no UI mockup elements. The image must 
depict only the physical object itself with its real surfaces, holes, 
and mechanical features. Treat this as a real-world product photograph, 
not a technical diagram. Any holes, mounting points, or slot positions 
must appear as actual physical features of the object (recesses, posts, 
bores) — never as drawn-on indicators.
```

**為什麼這麼嚴格**：圖檔會直接餵給 Tripo3D 等 AI 3D 服務生成 mesh，圖上的任何文字 / 線 / 標記都可能被 AI 詮釋為**幾何特徵或紋理**，污染最終 GLB。基於同一理由，**物件本體上也不出現任何印字標籤**（變體性格一律用造型、配色、色帶表達）。

# Part 1: Chassis（底盤）

**兼容約束**：所有 chassis 共用同一組接口 — 4 個 6mm 軸孔（軸距 96mm）、24mm 馬達座圓杯、60×30mm 電池倉、30×20mm 晶片倉、4 根 5mm 車殼柱、6 個 2mm 導輪螺絲座、前後各 1 個 12×8mm 武器安裝面（裝配時對應唯一的 `Mount_Weapon`，兩面擇一）。**輪廓和外形可變化，介面尺寸固定**；位置部分：軸孔 / 電池倉 / 車殼柱為 canonical 固定位置，馬達座 / 晶片倉 / 導輪座 / 武器面位置由各 chassis 自訂 —— 提示詞中給的位置即成為該 chassis 的 mount 位置（見 [零件與共用介面.md §6.1](../../建模參數/零件與共用介面.md#6-mount-結構表chassis--part-配對)）。

**Mount 系統說明（給玩家後續處理）**：圖中描述的 6 個導輪螺絲座位置，對應 chassis 端 `Mount_Roller_FL / _FR / _CL / _CR / _RL / _RR`；前後保險桿的武器安裝面對應**唯一的** `Mount_Weapon`（兩面擇一放置）。**這些 mount empty 不在圖上、不該被畫上去** —— 上傳後 Stage 2 編輯器會自動加標準命名 mount，玩家再拖放到對應的「物理孔位 / 安裝面」中心點即可（功能位置由提示詞中的物理特徵間接定義；命名與配對規則見 [零件與共用介面.md §6](../../建模參數/零件與共用介面.md#6-mount-結構表chassis--part-配對)）。

# Part 8: Weapon（武器）

**兼容約束**：安裝面 12×8mm 平面 + 2 個 2mm 螺絲孔（對應 chassis 前保險桿安裝面）。

**設計自由度**：武器外觀完全自由，**沒有 archetype 形狀粗檢**。系統依玩家在 GLB extras 宣告的 `passive`（`true` = 純物理被動）與 active 的 `weapon_mechanism`（`general / magnet / launch`）決定行為，物理表現由 mesh 接觸面 × 速度 × 材質自然決定（見 [零件與共用介面.md §3.7](../../建模參數/零件與共用介面.md#3-各-part-type-專屬欄位) / [零件與場景.md §9](../../零件與場景.md)）。下方 8.1–8.3 為公版三 archetype 的武器配置（[程式架構/builtin-assets.md §5](../../程式架構/builtin-assets.md)）、8.4 為 UGC 造型範例；玩家可自由發揮其他造型。

**朝向約定**：所有武器圖檔以「打擊端 / 槍口朝右（+X）、底部安裝面朝下（−Z）」生成，方便 Stage 2 fallback 依 mesh 主軸推斷 `Axis`（empty 的 +Z = 動作方向；推斷值標 `auto_inferred`，玩家可重標，見 [零件與共用介面.md §5.2](../../建模參數/零件與共用介面.md#5-empty-node-命名約定)）。

**Launch 武器工作流提醒**：`weapon_mechanism: launch` 需要 launcher 主體 + 子彈 sub-mesh。若 AI 只輸出單一 fused mesh，可在 Stage 2 用切分工具拆成 launcher / bullet，或於 Blender 先拆好並建立正確 hierarchy；增量拼接會保留來源內部 hierarchy，但不重新掛父層。每顆 bullet 都必須是 `weapon_main_mesh_node`（launcher_body）的**子節點**（發射順序 = 子節點順序、每顆各自宣告 material，見 [UGC機制.md §3.8](../../UGC機制.md)與 [零件與共用介面.md §3.7](../../建模參數/零件與共用介面.md#3-各-part-type-專屬欄位)）。

## 後續流程

1. 用每個提示詞各跑一張圖（24 張公版 + 1 張 UGC 範例可選）
2. **驗收標準**：每張圖必須清楚顯示 mandatory mount interface 那段描述的孔位、平面、尺寸 — 否則重 roll
3. 通過驗收的圖丟 Tripo3D（50K 面 + 1024 紋理——生成用高模；出貨優化與分級預算見 [程式架構/builtin-assets.md §7](../../程式架構/builtin-assets.md)）
4. 取得 GLB 後匯入 Stage 2 編輯器（公版使用等效 authoring 管線），完成 decimate、材質、Mount / Empty 與 weapon 結構編輯
5. 由 Stage 3 驗證 bbox、canonical feature deviation、Mount 完整性與 GLB extras schema
6. 兼容性測試：把不同 archetype 的同類部件放入 mockup 試組裝，確認無衝突
7. 通過後依用途分流：公版輸出到 `assets/builtin/parts/`；UGC 可存為 `local:` 或上 IPFS + ledger

## 約束自我校驗

如果某個 archetype 生出來的圖視覺上「為了戲劇化」破壞了 mandatory mount interface（例如 heavy chassis 把馬達座畫成方形而非圓形），**重 roll，不要將就**。介面不一致就是故障的開始。
