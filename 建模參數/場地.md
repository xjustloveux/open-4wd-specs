# 場地

> 本檔是建模參數的分冊 authority；穩定總入口與既有章節錨點見 [建模參數.md](../建模參數.md)。

## 8. 場地 GLB Root Extras

> **識別 marker**：場地與零件**共用**統一 marker `open4wd_version` + `type: "track"`（見 [§2](零件與共用介面.md#2-glb-root-extras--玩家宣告欄位零件--場地共用) 與 [版本規範.md §15](../版本規範.md)）。場地無專屬識別欄位，由 `type === "track"` 走場地解析分支；**載入已上鏈資產時**沒有 `open4wd_version` 的 GLB 拒絕載入（上傳解析不適用，見 [§2](零件與共用介面.md#2-glb-root-extras--玩家宣告欄位零件--場地共用)）。
>
> **主材質 `material` 沿用 [§2](零件與共用介面.md#2-glb-root-extras--玩家宣告欄位零件--場地共用)**：場地與零件統一在 [§2](零件與共用介面.md#2-glb-root-extras--玩家宣告欄位零件--場地共用) 表填 Root Extras `material`（main-mesh 預設材質、必填、fallback 用），本節不重複；sub-mesh 個別覆寫見 [§8.5](場地.md#85-材質指派materials-區塊sub-mesh-覆寫) `materials[]`。未在 `materials[]` 出現的 sub-mesh fallback 到 `material`（避免漏指派 sub-mesh 無材質）。

> **Editor 共同變形**：場地 Mesh 與 entity 可逐節點或多選後位移、旋轉、各軸縮放；
> Checkpoint／KillZone 的 scale 是 trigger box 尺寸。RoutePoint 與 RespawnPoint 是帶方向 Empty，
> 單選仍可依 surface frame 的合法 DOF 旋轉但不可縮放自身；多選縮放只改其相對共同 pivot 的
> 空間位置。操作契約見 [編輯器操作.md §1.2–§2.1](../編輯器操作.md)。

**〔TRACK-R-001〕** 場地的 route／checkpoint／empty 關聯、lap mode、重力／磁源、天氣、材質、
entity／destructible／kinematic、AABB 與資源預算等正式限制，必須由 canonical finalizer 與首次
ledger content admission 對實際 GLB 呼叫同一套純 canonical validator；只有 `reject` findings 是協定
拒收，編輯器 `warn` findings 不得升格。首次 admission 還必須重建完整 typed
`TrackPhysicsManifest`、核對 CID 所指 bytes 內的 version／digest／schema，並成功持久化精確
`(CID, version, digest)` receipt；receipt 寫入失敗即 fail closed。race runtime 只接受 ledger record、
embedded manifest reference 與本機 receipt 完全相符的 typed `AdmittedTrackAsset`，不得重跑幾何、
回讀 raw extras 或以六欄 track `PhysicsFingerprint` 代替 manifest 權威。

#### 8.2 `track.route[]` 結構（open / fixed 共用）

```jsonc
"route": [
  {
    "name": "RoutePoint_1",    // 對應 GLB 內同名 Empty Node（順序首尾 = 起終點；切線從 empty rotation 取得，見下方幾何模型）
    "width_m": 1.5             // 該點車道全寬（RP1 決定玩家上限；fixed 為 b-soft 走廊全寬，沿 spline 弧長線性插值到下一點）
  },
  { "name": "RoutePoint_2", "width_m": 1.5 },
  ...
]
```

寬度支援沿途變化（窄段、加寬段）；b-soft 邊界 = route spline 中心線 ± `width_m / 2`（僅 fixed 生效）。

**幾何模型（spline + 表面貼齊）**：

- RoutePoint = position（**貼 mesh 表面 ±0.005m**，`ROUTEPOINT_SURFACE_TOLERANCE_M`，Stage 3 檢核）+ 自訂 forward 切線
- forward 來源：empty 的 **-Z 軸**（Blender 慣例）；切線**限制在該點 surface 切線平面內**（編輯器在表面平面內讓玩家旋轉，1 DOF 繞 surface normal）
- route 為依各點 (position, forward) 的 **Hermite 三次 spline**；切線長度約定 = 該段弦長 × 1/3（deterministic）
- 局部 frame 的 up 軸 = surface normal（自動，無需創作者設定 → 自動支援 banked turn / 翻滾管道 / 立體迴圈內側）
- 加點預設 forward = 沿弦投影到 surface 切線平面（不主動旋轉時退化為折線手感）

**飛越段（兩 RoutePoint 中間無 mesh）**：

- 創作者**自然無法**在無 mesh 處放點 → spline 兩端點貼面、中段曲線浮空（編輯器視覺呈現「線飄越坑洞」，業界編輯器慣例）
- b-soft **僅當車「在表面」時觸發**（物理 contact + 100ms hysteresis；見 [遊戲機制.md §12.2](../遊戲機制.md)）；空中段完全不檢核（重力會把車拉回地面），落地後恢復
- spline 中段空中曲線形狀不必等同物理拋物線（純視覺，不影響玩法）

**起終點與方向（open / fixed 共用）**：

- `RP1` = 起點、`RPn` = 終點（序列首尾，無獨立起終點 Empty）
- **玩家上限**：`floor(RP1.width_m / START_GRID_CELL_WIDTH_M) clamp 至 TRACK_MAX_PLAYERS_HARDCAP`（同 [§5.4](零件與共用介面.md#54-場地專用-emptypascalcase)；常數與滿員需求寬度見 [protocol.md §3](../程式參數/protocol.md#3-protocolugcugc-規格約束)）
- **起跑格**：`RP1` position + `RP1.width_m` + `RP1.forward`（自訂切線）鋪車
- **終點正向**：chassis COM previous→current 對 RPn 定向平面由負側掃掠至正側；交點須在 RPn 左右寬度內，不使用步末速度
- **lap_mode**：`RP1 ↔ RPn` 中心距 < `LAP_MODE_LOOP_DISTANCE_M`（1m，[protocol.md §3](../程式參數/protocol.md#3-protocolugcugc-規格約束)）**且 route ≥ 3 點** → `loop`（起 = 終），否則 `linear`（恰 2 點一律 `linear`，無法構成迴圈幾何）
- **open = 恰 2 點（走廊關、自由跑）/ fixed = ≥ 2 點（走廊開、b-soft）**；恰 2 點 + 自訂切線 + 走廊開 = 直線或單段彎曲走廊
- **相鄰 RoutePoint 不可重合**（spline 段退化 → Stage 3 拒收）：相鄰中心距 < **0.1m**（`ROUTEPOINT_MIN_SPACING_M`）即視為重合；**例外**：`fixed` + `lap_mode: loop`（route ≥ 3 點）時 `RP1 ↔ RPn` 允許重合（這正是 loop 的定義，見 lap_mode 規則）。**特別禁止**：恰 2 點時（open 或 fixed 直線），RP1 ↔ RPn 重合會讓整條 route 退化 → 一律 Stage 3 拒收

| `weather.patch.friction_modifier`  | patch 內地表摩擦下降係數（0.3–0.9）                                                                                                                                                                                  | rain/snow 必填 | rain=0.65 / snow=0.5          |
| `weather.patch.rolling_modifier`   | patch 內滾動阻力上升係數（1.0–2.5；>1 = 拖感變重）                                                                                                                                                                   | rain/snow 必填 | rain=1.5 / snow=2.0           |

**三天氣溫度範圍**：normal -20~+40°C / rain +2~+35°C / snow -30~+2°C（重疊 +2°C 給雨夾雪）。

`weather.type: normal` 時 `patch.*` 全部**不可填**（Stage 3 拒收；比照 [§9.2](場地.md#92-entity-node-level-extras) `open_duration_ratio`「不適用欄位不可填」慣例）。

雨/雪 patch seed 由 `matchId + roundIndex + track manifest digest` 派生；整數 accumulator、固定最多 8 次候選與穩定 ordinal 見 [算式表.md §10](../算式表.md)。物理只修改 tire／roller 對靜態 solid 的 friction 與 rolling resistance；不修改 restitution。

**patch 視覺**：patch 在地表呈現**世界座標色偏**（`rain` 壓暗 / `snow` 提亮 base albedo），對齊物理 patch 的位置 / `radius_m` → 確保「看到的影響區 = 實際影響區」（純視覺、不影響物理，無 determinism 顧慮）。貼圖樣式美術自由；環境氛圍 VFX（落雨雪粒子 / 天色）不在功能 spec 規範。

**遮蔽（物理 + 視覺一致）**：finalizer 沿重力方向只保留每格第一個合格靜態 solid 表面，形成 typed exposure grid（每格高度量化到 1 mm）；grid 只保存在 canonical PhysicsManifest，root extras 不另存副本；因此橋面／屋頂本身可生成，其下方與隧道不生成。admission 獨立重建並核對；runtime、renderer 與 editor preview 共用 scheduler／descriptors，不讀 raw extras 或各自抽樣。動態遮擋不改 exposure。

### 8.5 材質指派（`materials[]` 區塊，sub-mesh 覆寫）

```jsonc
"materials": [
  { "mesh_node": "TrackSurface_Asphalt", "material": "asphalt" },
  { "mesh_node": "OffRoad_Sand",         "material": "sand" }
]
```

**`materials[]` = sub-mesh 個別覆寫**（單材質場地可留空）。任何 sub-mesh 未在此陣列出現 → fallback 到 [§2](零件與共用介面.md#2-glb-root-extras--玩家宣告欄位零件--場地共用) Root Extras `material`（main-mesh 主材質）。場景檢核由 material 的 `forbidden_scopes` 自動處理（[材質表.md §2](../材質表.md)）。至少 1 個 sub-mesh 對應材質後即可進 Stage 3（含 fallback：若所有 sub-mesh 都未在 `materials[]` 出現，主 `material` 即所有 sub-mesh 共用材質、合法）。entity node **不得**列入 `materials[]`（entity 材質為 node-level extras 權威，雙重宣告 Stage 3 拒收，見 [§2](零件與共用介面.md#2-glb-root-extras--玩家宣告欄位零件--場地共用) 優先序）。

### 8.7 碰撞體分段（`collision` 區塊，選填）

```jsonc
"collision": {
  "ground_cell_m": 8,              // 地面 XZ 格邊長（m）
  "wall_strips": [
    {
      "mesh_node": "Wall_Left",    // 牆 sub-mesh 節點名
      "rings": [                   // 沿路線的截面環序列（世界座標 m）；相鄰兩環之間＝一段
        [[0, 0, 0], [0, 1, 0], [0.2, 1, 0], [0.2, 0, 0]],
        [[0, 0, -2], [0, 1, -2], [0.2, 1, -2], [0.2, 0, -2]]
      ]
    }
  ]
}
```

| field | desc | required | 預設 / 範圍 |
| --- | --- | --- | --- |
| `collision.ground_cell_m` | 地面分塊的世界 XZ 格邊長（m）；公尺絕對值，空間縮放不改變 | ❌ | `TRACK_GROUND_CELL_M`（8），範圍 6–16，超出時 admission 拒收 |
| `collision.wall_strips[]` | 牆條帶清單；同一 `mesh_node` 不可重複宣告（Stage 3 拒收 `wall-strip-node-duplicate`，admission 同一判定拒收） | ❌ | 空陣列 |
| `wall_strips[].mesh_node` | 牆 sub-mesh 節點名；須為有幾何、非 entity 子節點、非 fluid 材質的靜態 solid 節點 | ✅ | — |
| `wall_strips[].rings` | 截面環序列 `[[x, y, z], …][]`；空間縮放（匯入 fit、編輯器縮放）同步縮放點座標 | ✅ | — |

整個區塊可省略：省略＝格邊長 8 m、無牆條帶，所有 solid region 都走地面分塊。走地面分塊的節點同材質者先合併再切塊，相鄰節點貼合的埋藏面在合併時剔除（[D-20261031-06](../decisions/D-20261031-06-同材質地面節點合併切塊.md)）。finalizer 把宣告烘進
PhysicsManifest 的 `collision`（`groundCellM`／`wallStrips`／`singleColliderNodes`，必填）；runtime
只讀 manifest，不讀本欄，切分與兩種邊界法線機制見
[physics-engine.md §2.7](../程式架構/physics-engine.md#27-場地靜態碰撞體分段)。

**宣告不吻合的處置**：admission 推導與 Stage 3 用同一份判定，依宣告順序逐條處理，不拒收也不靜默。
同一 `mesh_node` 重複宣告不屬不吻合，兩端一律拒收（見上表）。

- 節點是靜態 solid region，但環形狀不合法、規模超限或有三角不歸屬 → 該條宣告不切段，整個 region
  退回單顆碰撞體（一顆不分塊、不帶鬼三角的 trimesh），節點名寫入 manifest 的
  `singleColliderNodes`；Stage 3 給警告 `wall-strip-fallback`。
- 節點不存在、是 entity 子節點或 fluid → 沒有 region 可退回，宣告作廢，同樣給警告
  `wall-strip-fallback`。
- 警告帶 `nodeName` 與 `reason`，三角不歸屬時另帶第一個未歸屬三角的 `triangleIndex`；`reason` 是
  `wall-strip-node-missing`／`wall-strip-ring-shape`／`wall-strip-triangle-unassigned` 之一（規模超限
  歸為 `wall-strip-ring-shape`），編輯器依語系顯示原因文字。原因只出現在警告，不進 manifest。
- 退回單顆的 region 計入 piece 總數（每節點 1 顆）。單顆碰撞體在多車賽中通常較貴，Stage 2 統計
  分頁會標出成本等級。

**環序列規則**：

- 至少 2 環、每環至少 3 點、各環點數相同；每環須是有面積的閉合截面，相鄰環質心不可重合。
- 規模上限：每環點數 ≤ `TRACK_WALL_RING_POINTS_MAX`（64）、每條環數 ≤
  `TRACK_COLLIDER_PIECE_COUNT_MAX` + 1、所有條帶的段數（環數 − 1）依宣告順序累計 ≤
  `TRACK_COLLIDER_PIECE_COUNT_MAX`。推導端在三角歸屬之前檢查，超限的條帶退回單顆；manifest 的
  `wallStrips` 違反上限時拒收。
- 各環繞向一致：環的面積法向相對條帶前進方向同號。整條序列反向（環序與繞向同時翻轉）仍合法。
- 牆節點每個三角都必須歸屬某段：每環平面過該環質心、法向取 Newell 面積法向並統一朝條帶前進；
  三頂點皆落在環 k 平面之後、環 k+1 平面之前（含容差）的段為候選，因此彎牆的相鄰兩環可不平行。
  多個候選時取三角質心到段中心線（相鄰兩環質心連線）最近者，同距取最小段號；該距離不得超過
  兩環較大環半徑的 2 倍（側向守門，避免折返型牆的三角歸到另一腿）。
- 容差＝`1e-5 + maxAbs × 2^-22 + q`（m）。`maxAbs` 是該節點頂點與環座標的最大絕對值（float32
  ulp 量級）；`q` 是 Draco 位置量化（14 bit、量化範圍取該 mesh）步長的半對角上界＝節點世界
  AABB 對角線 ÷(2^14−1)×√3/2，未壓縮幾何為 0。finalizer、admission 與 runtime 對同一份解碼
  幾何以同式計算。已知限制：牆節點帶非等比縮放或 shear 時 `q` 會低估，宣告被判為不吻合而退回
  單顆（不會誤收為牆條帶）。
- 牆條帶與 entity 以外的靜態節點（地面塊等依地面格切塊的 solid）不逐 mesh 量化，而是共用一組量化網格：
  原點與範圍取這些節點頂點的聯集（各外擴一步），步長不超過 2^-11 m（約 0.49 mm）。相同座標因此解碼成
  逐位元相同的值，原本共面相接的地面塊在接縫處不會因量化產生台階（共用網格以 mesh 區域座標計；節點
  帶變換時不保證跨節點對齊）。

**作者規則**：

| 規則 | 內容 | 驗證與違反時 |
| --- | --- | --- |
| R1 牆地分離 | 牆（含護欄、岸壁）與路面、地面是不同 sub-mesh（solid 節點），各自指派材質 | 宣告的節點不存在、是 entity 子節點或 fluid → 宣告作廢＋警告 `wall-strip-fallback`（reason `wall-strip-node-missing`）；牆地未分離就不宣告，與地面一起分塊 |
| R2 牆為環序列條帶 | 每條牆是沿路線擠出的單一條帶（開口兩端或閉環），以截面環序列描述 | 環不合法或超出規模上限 → reason `wall-strip-ring-shape`；有三角不在任何相鄰兩環之間 → reason `wall-strip-triangle-unassigned`；皆退回單顆碰撞體（`singleColliderNodes`）＋警告 `wall-strip-fallback`，不拒收 |
| R3 地面分塊 | 路面與地面由 runtime 依 `ground_cell_m` 的世界 XZ 原點對齊格分塊；塊可為任意曲面，塊邊界法線由鬼三角推定；格線宜避免長距離與路面中心線重合 | 無作者動作；格邊長超出範圍時 admission 拒收 |
| R4 道具另立 | 岩石、建物、裝飾等非路面非牆的靜態體以 entity（[§9](場地.md#9-場地-entityglb-子節點物件)）或獨立 sub-mesh 宣告，不併入牆或地面節點 | 沿用 entity 機制，不另設檢核 |
| R5 作者端宣告 | 生成器或編輯器輸出 `wall_strips`；finalizer 只驗不推 | 無宣告＝無牆條帶 |
| R6 粒度 | 牆段自 `TRACK_WALL_SEGMENT_LENGTH_M`（0.25 m）起合併、單段上限 `TRACK_WALL_SEGMENT_LENGTH_MAX_M`（0.5 m）；地面格 6–16 m；piece 總數 ≤ `TRACK_COLLIDER_PIECE_COUNT_MAX`（8192） | piece 總數由 admission 與 Stage 3 依 runtime 同一套切分純函數計數（地面依質心格去重、牆依段長合併後的段組、退回單顆的節點各 1），超限拒收 `collider-piece-count-exceeded`；載入場地建立碰撞體時再檢查一次 |

地面分塊是多車成本的主要槓桿；牆宣告為選配，長直牆切成大量短段可能比整條更貴。

## 9. 場地 Entity（GLB 子節點物件）

> Entity = 場地 GLB 內帶 `entity_type` extras 標記的子節點。場地僅一個 GLB 檔，所有可破壞物件 / 動態物件 / 純裝飾物件皆為其子節點。**RoutePoint（起終點）/ Checkpoint 不是 entity**，而是場地設定（Empty Node，見 [§5.4](零件與共用介面.md#54-場地專用-emptypascalcase)）。

### 9.1 Entity 3 類

| 類別                 | physics                   | 用途                                              |
| -------------------- | ------------------------- | ------------------------------------------------- |
| `decoration`         | `visual_only` / `default` | 純裝飾或可破壞物件（靜態 collider）               |
| `kinematic_move`     | `default`                 | 動態位移（旋轉門 / 推板 / 升降平台 / 兩階段瞬移） |
| `kinematic_conveyor` | `default`                 | 輸送帶（表面速度推動接觸物）                      |

> **磁場物件實現**：「任意 entity + `magnetism_role: source` 材質 sub-mesh + Root Extras `magnet_source_strength_n`」即構成磁鐵物件。詳見 [§9.4](場地.md#94-磁源強度共用欄位) 與 [材質表.md §8.2](../材質表.md)。

### 9.2 Entity Node-level Extras

每個 entity 對應一個獨立 mesh node，`extras` 包含：

| field                    | desc                                                                                                                                                                                                                                     | 適用條件                                                            |
| ------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------- |
| `entity_type`            | 3 選 1 enum                                                                                                                                                                                                                              | 全部                                                                |
| `material`               | 統一材質表 enum                                                                                                                                                                                                                          | 全部                                                                |
| `physics`                | `default` / `visual_only`（visual_only 僅 `decoration`）                                                                                                                                                                                 | 全部（kinematic_* 強制 `default`）                                  |
| `destructible`           | 通用參數（任何 type 皆可設）；僅 `physics: default` 時生效                                                                                                                                                                               | 全部                                                                |
| `motion_curve`           | `sin`（連續往返）/ `step`（兩階段瞬移）/ `linear`（等速三角波）                                                                                                                                                                          | `kinematic_move`                                                    |
| `period_ms`              | 週期（ms，≥ `KINEMATIC_PERIOD_MS_MIN`（500，[protocol.md §3](../程式參數/protocol.md#3-protocolugcugc-規格約束)））                                                                                                                                                        | `kinematic_move`                                                    |
| `phase_offset_ms`        | 相位偏移（ms）                                                                                                                                                                                                                           | `kinematic_move`                                                    |
| `amplitude_m`            | 位移向量 `[x, y, z]`（m；**entity local frame**，entity 旋轉時位移方向隨之）；向量長度 ≤ `KINEMATIC_AMPLITUDE_M_MAX`（20 m）                                                                                                             | `kinematic_move`（與旋轉模式至少填一、可並用）                      |
| `rotation_axis`          | 旋轉軸單位向量 `[x, y, z]`（entity local、過 node 原點；解析時 normalize，同 [§8.4](場地.md#84-物理環境physics-區塊必填可給預設) `gravity_direction` 慣例）                                                                                     | `kinematic_move` 旋轉模式（與 `rotation_amplitude_deg` 成對）       |
| `rotation_amplitude_deg` | 1–360：**360 = 連續旋轉**（等角速度、`period_ms` = 一圈、`motion_curve` 不適用）/ **< 360 = 往返揮動**（依 `motion_curve`）；語義比照 [§3.7](零件與共用介面.md#37-weapon-專屬) `weapon_max_angle_deg`                                                     | `kinematic_move` 旋轉模式                                           |
| `open_duration_ratio`    | period 中位於位移 / 旋轉終點的比例（0–1）；**僅 `step` 有「停留」語意**，`sin` / `linear` 為連續運動無此欄位                                                                                                                             | `kinematic_move` + `motion_curve: step`（其他 motion_curve 不可填） |
| `conveyor_velocity_m_s`  | 表面速度（沿 entity 自身 -Z 軸，Blender forward 慣例，與 [§5.4](零件與共用介面.md#54-場地專用-emptypascalcase) RoutePoint forward 一致），m/s；絕對值 ≤ `CONVEYOR_VELOCITY_M_S_MAX`（10）、負值反向                                                       | `kinematic_conveyor`                                                |
| `auto_fragments`         | Stage 3 預烘焙 `{version,count,method,total_volume_loss_pct,fragments[{fragment_index,seed_m,volume_m3}]}`；canonical current PhysicsManifest 保存同一完整純視覺 descriptor，不含 fragment mass／collider／pose／velocity。runtime 只讀 typed manifest，不讀 raw extras。 | `destructible: true` 的 entity（僅這些 entity 烘焙）                |

**Kinematic 固定幀驅動**：finalizer 把 `period_ms／phase_offset_ms` 正規化為 60Hz 整數 frame，runtime 以 `state(frame) = f(frame, periodFrames, phaseOffsetFrames, amplitude / rotation, motion_curve)` 推導，禁止 wall clock；sin／旋轉使用版本固定 deterministic 近似。**運動模式**：平移（`amplitude_m`）與旋轉（`rotation_axis` + `rotation_amplitude_deg`）至少填一、可並用（並用 = 螺旋運動，如旋轉升降平台）；皆沿 entity local frame。**連續旋轉的碰撞形狀**：`rotation_amplitude_deg: 360` 的 entity 於烘焙期逐 collider 節點對 `rotation_axis` 判圓（容差 `ROLLING_SURFACE_ROUNDNESS_EPSILON_M`），判圓的盤面以 cylinder 承載、非圓（擋板、粗面多邊形）維持每節點 AABB box——要旋轉圓盤物理上是圓，網格圓周須夠細（半徑 0.5m 約需 ≥96 邊）；振盪型（< 360）一律 box（[D-20261020-02](../decisions/D-20261020-02-旋轉面形狀分類移至烘焙期.md)）。

### 9.3 destructible 通用參數

| name   | field          | desc                                                                                               | required         | auto | edit                                    |
| ------ | -------------- | -------------------------------------------------------------------------------------------------- | ---------------- | ---- | --------------------------------------- |
| 可破壞 | `destructible` | 任何 entity_type 都可加；**僅 `physics: "default"` 時生效**；mass / 破壞閾值由材質自動算 | ❌（預設 false） | ❌   | ✏️ Stage 2 checkbox；visual_only 時灰掉 |

破壞行為（fatigue ≥ 1.0 或單次 stress > `ultimate × K_STRESS_BURST_FACTOR`，K 預估 1.5，見 [程式參數.md](../程式參數.md) / [算式表.md §7](../算式表.md)）：

1. 立即停止 kinematic 驅動（kinematic_move 停止往返、kinematic_conveyor 表面速度歸零、磁源 sub-mesh 失效）
2. 停用 intact body／colliders／完整 visual；不得把 intact body 改成 Dynamic
3. 不建立、啟用或保留 fragment body／collider／sensor；碎片不參與物理、傷害或路障
4. presentation 由 `entityIndex + breakFrame + descriptor/presentation version` 重建，不保存逐片 pose／velocity
5. 車輛與場地碎片共用 `VISUAL_FRAGMENT_LIFETIME_MS`（5000ms）與 `VISUAL_FRAGMENT_FADE_MS`（1000ms）；逾期不生成

可破壞性決策見 [材質表.md §10](../材質表.md)；耐受度因子族算式見 [算式表.md §7](../算式表.md)。

### 9.4 磁源強度共用欄位

| name     | field                      | scope                                                | desc                                                                                                                                                                                                                                                                                               | required     | auto | edit                                                             |
| -------- | -------------------------- | ---------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------ | ---- | ---------------------------------------------------------------- |
| 磁源強度 | `magnet_source_strength_n` | 零件 = Root Extras / 場地 entity = node-level extras | 主動磁源強度（牛頓）；**正常僅場地 entity / 地板（`magnet_floor`）使用**——車輛部件（含 passive 武器）正常無 `source` 材質、異常出現即設定錯誤的 fallback 防護（[材質表.md §8.2](../材質表.md)）；**僅當該物件含 `magnetism_role: source` 材質 sub-mesh 時生效**；未宣告 = 0（等於有磁源材質但未磁化） | ❌（預設 0） | ❌   | ✏️ Stage 2 數值欄位，範圍 0–10（`MAGNET_SOURCE_STRENGTH_N_MAX`） |

**物件「是磁鐵」條件**（兩者缺一無效）：

1. 至少一個 sub-mesh 的材質 `magnetism_role: source`
2. `magnet_source_strength_n > 0`

N 極方向：sub-mesh **面積加權平均法向**（pre-bake 入 extras、多 sub-mesh 各自一向量；退化 fallback node +Z，[材質表.md §8.3](../材質表.md)）。

互動算式詳見 [材質表.md §8.4](../材質表.md) + [算式表.md §5](../算式表.md)。
