# D-20261115-09｜輸送帶 entity 至少要有一個非流體節點

## 背景與驅動力

[D-20261115-08](D-20261115-08-場地entity的流體材質節點是跟著剛體的sensor.md) 讓 entity 的流體材質節點成為
sensor，並允許不可破壞的 entity 只有流體節點。輸送帶（`kinematic_conveyor`）因此可以全部節點都是流體：輸送
速度只設在實體碰撞體上，流體 sensor 不產生接觸，這種 entity 的輸送速度沒有任何作用，作者也不會收到提示
（issue 001420）。

同一張 issue 另有一項：entity 被破壞後，附著在它上面的子彈流體區要到下一次物理步進才停用，破壞後的下一幀
還會再套用一次流體效果，與 entity 自身的流體 sensor 在破壞的當下就停止回報不一致。

## 考慮過的選項

- **當成設定錯誤而拒收**（採納）：輸送帶 entity 至少要有一個非流體的節點。
- **做成水流區**：只有流體區的輸送帶讓車輛零件在流體區內沿流向受力。這是新的玩法機制，需要另外設計受力模型，
  不在這裡處理。
- **維持現狀，只在編輯器加警告**：留下一個沒有效果的設定組合。不採用。

## 決定

- `kinematic_conveyor` 的 entity 至少要有一個非流體的節點；全部節點都是流體時，編輯器檢核、manifest 推導與
  manifest 重驗都拒收。D-20261115-08「不可破壞的 entity 可以只有流體節點」不適用於輸送帶。
- 輸送帶有實體帶面時，底下的流體子節點照常是掛在同一個剛體上的 sensor。
- entity 被破壞時，附著在它上面的子彈流體區在破壞的當下一併停用，不等下一次物理步進。

## 後果與影響

- 只有流體節點的輸送帶場地不再能定稿或通過準入。專案為 `pre_launch`，沒有既有資產需要遷移。
- entity 被破壞後的下一幀，附著的子彈流體區不再套用流體效果。
- 現況規格：[建模參數/場地.md](../建模參數/場地.md) 第 9.1 節。

## 定案紀錄

2026-11-15 使用者裁決：只有流體節點的輸送帶當成設定錯誤而拒收；水流這種機制不在這裡處理。子彈流體區在
entity 被破壞的當下停用，是處理者依既有規則（entity 被破壞後流體不再回報）補齊的一致性修正。
