# D-20261114-01｜場地物件相位偏移的幀換算與第 0 幀姿態

## 背景與驅動力

[建模參數/場地.md](../建模參數/場地.md) 第 9.2 節規定 `kinematic_move` 的 `period_ms` 與 `phase_offset_ms`
由 finalizer 正規化為 60Hz 的整數幀，但沒有寫換算與捨入方式，也沒有寫負值或超過週期的相位如何處理。

issue 001368：推導 PhysicsManifest 時 `phase_offset_ms` 沒有被讀取，`phaseOffsetFrames` 一律為 0，
比賽中所有物件同相；編輯器預覽卻會套用相位。修正時必須先把換算規則定下來。另外，物理世界原本以
`initialPose` 建立 kinematic body，相位不為 0 時 `initialPose` 不是第 0 幀的位置，第一次 step 會把
整段相位位移當成一幀內的位移。

## 考慮過的選項

- **相位限制在 0 到週期之間，超出即拒收**：規則最嚴，但作者以負值表示「提前」是自然的寫法。
- **相位對週期取模**（採納）：任何有限數值都合法，換算後落在 0 到週期幀數之間。

## 決定

- `periodFrames = max(1, round(period_ms × 60 ÷ 1000))`（既有行為，補記於規格）。
- 相位先對週期取餘數再換算成幀：`phaseOffsetFrames = round((phase_offset_ms mod period_ms) × 60 ÷ 1000)`，
  再對 `periodFrames` 取模，負值加上 `periodFrames`，結果落在 0（含）到 `periodFrames`（不含）之間。
  `mod` 是保留被除數正負號的浮點餘數。先取餘數有兩個用意：相位等於週期的整數倍時一定是 0（即使週期本身
  不是整數幀）；餘數的絕對值小於週期，乘 60 不會讓極大的有限相位溢位。負值與超過週期的相位都合法，未宣告視為 0。
- `phase_offset_ms` 有宣告時必須是有限數值，否則拒收（驗證碼 `kinematic-phase-offset-invalid`）。
- 物理世界以第 0 幀的姿態建立 kinematic 物件的 body，不以 `initialPose` 建立。`initialPose` 仍是
  運動函式的基準姿態（行程為 0 時的位置）。

## 後果與影響

- 設定了相位的場地從此在比賽中依相位運動。
- 相位為 0 時，第 0 幀的姿態與基準姿態的關係依曲線而定：`linear` 的平移逐位元相同；`step` 在停留視窗不含
  第 0 幀時（`open_duration_ratio` 預設 0.5 即是）平移逐位元相同，比例接近 1 使視窗由第 0 幀開始時則已在終點
  （issue 001371）；`sin` 的行程在第 0 幀是決定性餘弦近似的餘數，約為負 3.3×10⁻¹⁰，平移因此偏離基準約幅度的
  3.3×10⁻¹⁰ 倍、方向與幅度相反，`sin` 的往返旋轉同樣帶這個餘數；`step` 的停留視窗含第 0 幀時，往返旋轉與平移
  一樣已在終點；其餘情形（`linear`、停留視窗不含第 0 幀的 `step`、360 連續旋轉）的旋轉只差四元數正規化的浮點捨入。
  含 `sin` 物件的場地，物件的初始物理狀態因此有這個量級的改變，屬物理共識行為變更；三個公版場地沒有
  kinematic 物件，不受影響。
- 相位以幀為單位捨入，取餘數後絕對值小於半幀（約 8.3 毫秒）的相位等於 0；恰在半幀邊界的值，捨入方向取決於
  浮點運算的結果。
- 編輯器預覽原本以連續毫秒計時；issue 001384 已改為與比賽共用同一套幀換算，預覽與比賽的週期、相位、
  step 停留視窗一致。
- 現況規格：[建模參數/場地.md](../建模參數/場地.md) 第 9.2 節。

## 定案紀錄

使用者指示先修這一項。
