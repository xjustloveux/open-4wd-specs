# D-20261122-07｜仲裁 attestation 以帳本事件收集

## 背景與驅動力

仲裁的面板案結果必須附上不少於 quorum 份的面板 attestation 才會被 fold 收下
（[moderation.md](../程式架構/moderation.md) MOD-R-042、MOD-R-046）。規格寫 attestation 是期滿後的機械簽署、成員上線
即補簽，但沒有定義 attestation 怎麼從面板成員送到寫結果的節點；實作也沒有任何傳輸，簽署與組結果的函式沒有正式
呼叫者。所有面板案期滿後都寫不出結果：判定成立的檢舉不會下架、不會扣分，上傳期案的相似審查狀態不會解除
（issue 001464）。

## 考慮過的選項

- **attestation 寫進帳本、fold 記入狀態（採用）**：新增單簽事件，成員各自上線時送出，fold 驗證後記入帳本狀態，
  任何節點從狀態收集。不需要成員與寫入者同時在線，符合「蒐集無時窗」；帳本多出永久事件，狀態多一個欄位。
- **attestation 寫進帳本、收集時掃 log**：不改狀態，但案件久未結案時每次要讀的 log 範圍只增不減，讀取成本與
  失敗風險隨帳本成長。不採用。
- **gossip 請求與回應、不進帳本**：不新增事件型別，但成員與寫入者要同時在線，或要快取並反覆廣播，另需限流與
  濫發處理。不採用。
- **上傳期案到期自動解除**：只能止血，判定成立仍不會下架，還會改變上傳期案的結案語意。不採用。

## 決定

- 新增帳本事件 `arbitration-attest`（單簽）：欄位為案件 id、簽署者、聲稱的結果與比例、對 attestation digest 的
  簽章。
- 守門（收件驗證與 fold 共用）：結果為三個字串值之一且比例為 0–100 的整數、案件仍待結案（案錨存在、未撤回、案錄與這個案件 id 都尚無結果、檢舉案未逾期，且檢舉案的
  案件 id 逐字等於案錄上的寫法）、簽署者非兩造、簽署者通過仲裁者的穩定資格（年資與場數）、時戳
  不早於面板案可能結案的下界（含訊息時戳容差）、attestation 簽章有效。准入層另外實際驗 attestation 簽章。簽署者是否為面板成員、
  結果是否正確，守門無法判定，由收集端過濾，結果事件仍經 panel-signature-set 恆驗。
- fold 通過守門才把 attestation 記入狀態的 `pendingAttestations`：同一案同一簽署者只留最新一份；結果事件收下時
  清除該案 canonical id 下的條目（條目只記在 canonical id 下）；記入新條目時順帶清掉
  已不再待結案的案件上的殘留。
- 收件驗證在本機狀態鏡像看不到待結案的案件或簽署者資格時延後重審，其餘拒因直接拒收。
- 仲裁推進器處理面板案：本機是面板成員而狀態裡沒有自己那份相符的 attestation 時先送出（送出成功後，同一個
  推進器對同一案不再重送同樣的結果與比例；本機 replay 的內容改變時會再送一筆）；再從狀態讀該案的 attestation，只採用面板成員、聲稱內容與自己 replay 相同的，達 quorum 就寫入結果。
  收集不讀 log。
- `arbitration-attest` 列入「不需玩家 onboarding 的協定寫入」。

## 後果與影響

- 面板案（含票不足流局與重抽輪池不足的流局）期滿後可以結案，判定成立的作品案接著下架。
- 帳本的永久事件型別由 20 種增為 21 種（封閉目錄 22 型別）。專案尚未公開，不需遷移。
- 任何人都能把 `arbitration-attest` 寫進帳本（受帳本的工作量准入約束），但只有通過守門的才進狀態。通過穩定資格
  的非兩造玩家即使不是該案面板成員，條目也會進狀態；這些條目不會被收集，在結果收下時清除。
- 狀態中每案的條目數不超過通過穩定資格的非兩造玩家數；已不再待結案的案件上的殘留（例如逾期未結的檢舉案），要等下一筆任何案件的
  attestation 被記入時才清除。
- 開放案清單不再列出已有結果的上傳期案（判定成立後、下架前仍在相似審查中的作品），也不列出案件 id 已有結果的
  檢舉案。
- 修改 D-20261122-04：推進器不再只寫不需要 attestation 的事件，也送出 attestation 並寫入面板案結果；每收到一筆
  attestation 也會排程推進。
- 現況規格：[moderation.md](../程式架構/moderation.md)、[ledger-admission.md](../程式架構/ledger-admission.md)、
  [ledger-checkpoint.md](../程式架構/ledger-checkpoint.md)、
  [資料系統.md](../資料系統.md)、[檢舉與仲裁.md](../流程/檢舉與仲裁.md)、[信譽系統.md](../信譽系統.md)。

## 定案紀錄

2026-11-22 由使用者裁決：attestation 以帳本事件收集，搭配仲裁推進器；同日再裁決 attestation 由 fold 記入帳本
狀態，不以掃 log 收集。
