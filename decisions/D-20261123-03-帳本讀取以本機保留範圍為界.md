# D-20261123-03｜帳本讀取以本機保留範圍為界

> **2026-11-24 關聯追補**：[D-20261124-04](D-20261124-04-條目有效性以檢查點切面與確定性時鐘判定.md) 修訂本檔的「本機保留範圍」：
> 範圍終點的目前 heads 改為檢查點切面的極大元素，孤兒條目雖仍在本機但不屬保留範圍。

> **2026-11-26 關聯追補**：[D-20261126-01](D-20261126-01-定稿先於公告與採納流程補強.md) 修訂本檔決定段的四處：
> 「重啟時 log 的邊界就是以 effective checkpoint 的 heads 重建的，兩者相同」改為以 control 的 `latest` 重建，衝突隔離後與
> effective 不同；定稿時找既有公告的範圍改為本機保留範圍，讀取失敗時公告留在待送出清單、定稿結果不變；只因本機切面容量被拒
> 而未落盤的公告也可進採納流程，它不在啟動掃描的範圍內；開庫時最新 checkpoint 的狀態塊讀不到，改為開庫成功並進入 recovery。

## 背景與驅動力

客戶端不必保留已被 finalized checkpoint 覆蓋的事件，本機 entry store 在配額滿載時會淘汰這些條目
（[ledger.md](../程式架構/ledger.md) 第 10 節，LEDGER-R-073）。但 event log 埠仍提供從 genesis 走到目前 heads
的全量走訪，啟動時的 checkpoint 公告掃描、定稿重試時找既有公告、`getAllEvents` 與不帶參數的 `readEvents`
都建立在它上面。這兩件事的前提互相矛盾：條目一旦被淘汰，全量走訪就讀不到中間的條目而失敗，其中啟動掃描
失敗會讓帳本開不起來（issue 001502）。以 checkpoint 為起點的區間讀取不受影響。

另一處同類情形是重建：已有 checkpoint 而它的狀態塊暫時讀不到時，重建會退回從 genesis 重放，同樣假設本機有
完整歷史；[ledger-checkpoint.md](../程式架構/ledger-checkpoint.md) 的 LEDGER-R-048 只允許沒有 checkpoint 時
從 genesis 重建。

## 考慮過的選項

- **讀取一律以本機保留範圍為界，刪除全史讀取介面（採用）**：log 的走訪從自己的淘汰邊界開始；各呼叫端改讀
  自己真正需要的那一段；對外不再有「讀全部事件」的介面。介面與實際保證一致，不需要呼叫端處理不完整的結果。
- **保留全史介面，條目不全時回報不完整**：每個呼叫端都要自行決定拿到部分結果時怎麼辦，而現有呼叫端沒有一個
  真的需要 checkpoint 之前的條目；保留介面只會讓新程式繼續依賴本機不保證的資料。不採用。
- **缺條目時向其他節點補抓**：補抓需要對方仍保留該條目，同樣沒有保證；還要為補抓的條目另訂配額與驗證流程，
  並讓啟動時間取決於網路。checkpoint 的用途正是讓節點不必持有更早的歷史。不採用。

## 決定

- event log 埠的走訪範圍是「本機保留範圍」：從 log 自己的淘汰邊界（不含邊界條目）到目前 heads；還沒有邊界時
  是 genesis 到 heads。埠上沒有讀全部條目的專用入口。以空的起點呼叫區間走訪仍等於從 genesis 走訪：尚無 checkpoint
  時的重建與狀態推導即如此讀取；已有 checkpoint 後，走訪經過已被淘汰的條目就會失敗，呼叫端不得依賴它成功。
- 起點取 log 自己的邊界，不取 checkpoint store 的 effective 指標：可淘汰的範圍由 log 的邊界決定，effective
  指標在衝突隔離時會退回較早的 checkpoint，log 的邊界不隨之後退。這項區別只存在於同一個 runtime 內；重啟時 log
  的邊界就是以 effective checkpoint 的 heads 重建的，兩者相同。
- 啟動時的公告掃描讀本機保留範圍。接續最新已採納 checkpoint 的後續 checkpoint，其公告必在邊界之後。
- 定稿重試時找既有公告，只讀本次 checkpoint 的 heads 到目前 heads。目前 heads 含有不經過這組 heads 的分支、走訪
  以連續性錯誤拒絕時，視為沒有既有公告並照常寫出（重複的公告在採納時冪等）；走訪因其他原因失敗時定稿失敗。
- 刪除 `getAllEvents`；`readEvents` 必須指定 checkpoint，該 checkpoint 不在本機時明確失敗，不退回全量。
- 重建在已有 checkpoint 而狀態塊讀不到時失敗，不退回 genesis 重放；之後由 recovery 重試
  （[D-20261123-04](D-20261123-04-帳本recovery失敗後依退避重試.md)）。

## 後果與影響

- 不改共識規則、事件格式與 wire；改變的是本機讀取的範圍與對外介面。
- 需要「現在」的呼叫端讀已折疊狀態的共識時鐘，不再掃事件。
- 啟動掃描不再讀邊界之前的公告。與已採納 checkpoint 同 previous 的 sibling，若其公告已被該 checkpoint 的 heads
  涵蓋，重啟掃描不保證再讀到它，同 previous sibling 的隔離（LEDGER-R-042）對它只在公告於執行中到達、或仍落在掃描
  範圍內時觸發。先前從 genesis 掃描時，只要條目仍在本機就會讀到；本決策未就這項差異另作取捨。
- checkpoint 之前的事件在一般節點上不可讀；需要歷史內容的功能必須以 checkpoint 狀態承載，或向保留完整歷史的
  服務查詢。
- 專案尚未公開，被刪除的介面沒有已發布的呼叫端，不提供相容層。
- 現況規格：[ledger.md](../程式架構/ledger.md)、[ledger-checkpoint.md](../程式架構/ledger-checkpoint.md)、
  [interfaces.md](../程式架構/interfaces.md)。
