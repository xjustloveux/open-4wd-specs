# D-20261124-01｜帳本檢查點身分與簽章憑證分離

## 背景與驅動力

檢查點本體原本含簽章，定稿要求恰好 quorum 份。多位簽署者時，不同節點對同一份提案湊到不同組簽章各自定稿，
就會得到同一個 previous 的不同檢查點 CID，被判為簽署者重複簽署而全網隔離，而隔離目前沒有解除路徑
（issue 001507）。正式產生檢查點的路徑（issue 001535、001538）以多人為設計目標，必須先消除這個非惡意的衝突來源。
另外，空帳本無法產生首個檢查點：本體要求 `log_head_cids` 非空。

## 考慮過的選項

- 維持現狀，以單一定稿者避免不同簽章組合：與「任何節點可定稿」及簽署者離線時的活性衝突，不採納。
- 定稿時以確定性規則挑選簽章子集：各節點看到的簽章不同時仍可能選出不同子集，不採納。
- 檢查點身分只看本體、簽章另成憑證（採納）。

## 決定

- 檢查點 CID 是本體 canonical bytes 的 CID；本體不含簽章，新增 `round` 與 `next_signer_set_cid`（成形後狀態中的
  治理 signer set，覆核時與重算結果比對）。previous 為 null 的首個檢查點允許 `log_head_cids` 為空陣列，狀態由創世直接成形。
- 簽章以檢查點憑證表示：附 signer 的 `{ signer, sig }` 陣列，signer 嚴格升冪。驗證嚴格：任一簽章無效、signer 不屬
  前代 signer set 或份數不足 quorum 即整份拒絕。定稿與採納接受至少 quorum 份；本機保存第一份驗證通過、依 signer
  取前 quorum 份的憑證，之後不替換；本體與憑證都保存後才可設為最新檢查點。
- 衝突隔離以本體 CID 判定；同一本體配不同簽章組合是同一個檢查點。採納佇列與負面快取改以「本體 CID 加簽章陣列雜湊」
  為鍵，壞簽章的公告不會連帶封鎖同一本體。
- 定稿公告事件由 `ledger-checkpoint` 改名為 `ledger-checkpoint-certificate`（型別 `LedgerCheckpointCertificateEvent`），
  攜帶本體 CID 與裁成 quorum 份的憑證簽章。含 `expiresAt` 的提案物件（介面層 `CheckpointProposal`、
  實作層 `LedgerCheckpointProposal`）移除，提案改為帳本事件（見 [D-20261124-02](D-20261124-02-檢查點多簽協定以帳本事件與輪次鎖定運作.md)）。
- 兩種採納模式都驗 `next_signer_set_cid` 與成形後狀態的治理集合相符，且大小為 1 或至少 3。
- 鏈重生證明 `InitialCheckpointProof` 新增與檢查點鏈逐項對應的憑證 CID，逐代以當代 authority 驗憑證，authority 由
  本體的 `next_signer_set_cid` 推進，只有最後一代取得完整狀態。

## 後果與影響

- 誠實節點之間不再因簽章組合不同而衝突；只有簽署者真的對同一 previous 簽了兩份不同本體時才隔離。
- 各節點保存的憑證都 canonical 且自足可驗，但可能是不同的簽章組合，規格不宣稱跨節點 bytes 相同。衝突證據的
  `equivocatedSigners` 取兩份本機憑證的 signer 交集，只作證據，不保證列出所有雙投者。
- 本體 wire、公告事件與鏈重生證明 descriptor 都改變；專案處於 pre_launch，不做相容或遷移。pinning 的 vendored
  帳本棧與自身程式隨 issue 001488 同步。新節點目前只能從本機保留範圍內的公告取得憑證，更早各代憑證的取得屬 issue 001527。
- 修訂 [D-20260725-03](D-20260725-03-checkpoint前代authority與pinning切換完成.md)：authority 仍是前一個已採納
  檢查點的狀態，但下一代 signer set 改由本體的 `next_signer_set_cid` 記錄並在兩種採納模式驗證。
- 修訂 [D-20260814-19](D-20260814-19-鏈重生完整來源檢查點證明.md)：逐代推進 authority 改讀本體的
  `next_signer_set_cid`，簽章改以憑證驗證，不再逐代取得完整狀態。
