# D-20261113-11｜音樂靜音時不載入 BGM

## 背景與驅動力

[D-20261113-04](D-20261113-04-靜音旗標與頂欄喇叭鈕.md) 規定「靜音期間 BGM 照常載入與轉場」，目的是取消靜音時立刻有聲音。
音樂靜音的預設值是開啟，所以新玩家在取得首次使用者手勢之後，每當該播的曲目檔案改變，就會下載並整檔解碼一首聽不到的曲子。
以預設主題來說，首頁、車庫、編輯器、瀏覽、房間與結算共用同一個檔案，會換檔的是進出比賽頁。

issue 001365：BGM 以 Web Audio buffer 循環播放，整檔解碼後常駐記憶體（48 kHz 立體聲每分鐘約 23 MB）。預設主題的
比賽曲長 117 秒、檔案 1.8 MB，解碼後約 43 MiB。在比賽頁，這段下載與解碼和開賽載入同時進行：issue 001363 的對照量測中，
本機以 4 倍 CPU 節流擋掉全部音訊檔（不只 BGM），遮罩到倒數由 21.3 到 22.7 秒變為 20.0 秒。

## 考慮過的選項

- **維持現況**：取消靜音立刻有聲音；預設靜音的玩家持續付出下載、解碼時間與記憶體。
- **靜音時仍載入，但比賽頁延到呈現就緒之後才載入**：保留「取消靜音立刻有聲音」，只把成本移出開賽路徑；
  流量與記憶體沒有省下，音訊服務還要知道比賽頁的呈現狀態。
- **靜音時不載入**（採納）：靜音期間只記下目前該播的曲目，取消靜音才載入。

## 決定

- 音樂靜音時不開始新的 BGM 下載與解碼。路由與主題變更照常決定目前該播的曲目，但不建立播放通道。
- 取消靜音時載入目前該播的曲目，開始播放後淡入；尚未取得使用者手勢時仍等首次手勢。
- 播放中或載入中切到靜音時，立即停止並釋放通道，不走淡出。播放中的曲目隨之釋放解碼後的 buffer；
  載入中的那一次沒有中止機制，已發出的取檔與解碼仍會跑完，結果才丟棄。
- 音效靜音的行為不變：靜音只讓音效軸的 gain 為 0，取消靜音即回到原音量。
- 靜音旗標、預設值、設定頁與頂欄喇叭鈕都不變。

## 後果與影響

- 音樂維持靜音的玩家不再下載與解碼 BGM。
- 取消靜音後要等曲目下載與解碼完成才有音樂；等待多久沒有量測。
- 靜音期間換頁再取消靜音，播的是目前頁面的曲目。
- D-20261113-04「取消靜音後立刻聽到目前場景的 BGM」不再成立，改為「取消靜音後載入並播放目前場景的 BGM」。
- 現況規格：[程式架構/audio-system.md](../程式架構/audio-system.md) 第 5 節。
- 與既有決策的關係：amends [D-20261113-04](D-20261113-04-靜音旗標與頂欄喇叭鈕.md) 中音樂靜音期間的載入行為；
  其餘各點不變。

## 定案紀錄

2026-11-13 追查開賽載入變慢（issue 001363）時發現靜音仍載入 BGM 是次要來源；使用者在「靜音時不載入」、
「維持現況」與「只延後、不取消」之間裁決採第一項。
