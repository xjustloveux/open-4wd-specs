# D-20260820-01｜預發布內建資產延後交付與兩段發布鏈

## 背景與驅動力

首次公開候選仍缺可證實公開與再散布權利的 27 個正式 builtin GLB。若要求所有 source backup 與
三個 self-contained service repo 都等待最終資產，會把不依賴資產的公開安全與部署工作一併阻塞；
若把現有暫行 bytes 直接放進公開 Git，又會讓不完整的權利證據進入永久歷史。開發測試同時需要
區分「已核准延後交付」與一般缺檔，不能以靜默 skip 冒充 asset-ready。

## 考慮過的選項

- 所有 repo 等正式 GLB 後一起備份與公開：邊界安全但造成不必要的跨 repo 阻塞，否決。
- 暫行 GLB 先進 private／public Git，日後再補授權：Git 歷史仍可能公開未證實 bytes，否決。
- 明示 delivery state、僅開發期有限 skip，並採 source/service 與 final main 兩段發布（採納）。

## 決定

- `public/assets/builtin-delivery.json` 是 version 1 的交付權威，狀態只有
  `deferred-prelaunch` 與 `delivered`。未知、缺失或 malformed 狀態一律 fail closed。
- `deferred-prelaunch` 只允許四類明列的 asset-dependent tests 在 development profile 顯式 skip，
  並輸出 D-20260820-01。strict、nightly、release、asset-ready 及一般非授權缺檔仍失敗。
- `delivered` 必須具備 27 個正式 GLB、完整 manifest metadata、strict 載入／物理／效能／E2E、
  人工驗收及 `public/assets/builtin/PROVENANCE.md`。該文件逐項提供生成或取得來源、方案與條款
  證據、輸入素材權利、輸出授權、產出日期與人工核准；機械 gate 只驗完整非 placeholder，實質
  權利判斷由人類審閱。
- 權利來源未證實的暫行 GLB 不進公開 Git 歷史；本機 bytes 可保留供開發，不因改名或 codebase
  採 MIT 就取得公開與再散布權利。
- `open-4wd` 可先建立不含暫行 GLB 的 private source backup。Pinning、Signaling、TURN 在各自
  self-contained CI、完整歷史公開安全檢查及 vendored content-hash provenance 通過後，可先於
  `main_source_baseline_sha` 公開，不建立對 private main 的暫時遠端讀取權限。
- 正式資產與 asset-ready 證據完成後才形成 `main_source_baseline_sha`。Final main SHA 上的 remote
  provenance gate 再綁三個 service repo；首次公開後若任何 vendored path 漂移，舊同步證據立即
  失效並重開驗證。

## 後果與影響

source backup 與 service template 公開不再被尚未交付的 GLB 無限期卡住，但任何 asset-ready 或
release 聲明仍需完整成品與權利證據。開發 CI 會清楚列出授權的 deferred skip，不會把 missing title
視為通過；最終 main baseline 及 remote provenance 則保留原本的 fail-closed 強度。
