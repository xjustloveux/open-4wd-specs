# D-20261124-03｜常駐治理簽署工具

## 背景與驅動力

檢查點的多簽協定（[D-20261124-02](D-20261124-02-檢查點多簽協定以帳本事件與輪次鎖定運作.md)）定義了提案、投票、鎖定與定稿，
但沒有任何執行者會在固定時間提案與投票（issue 001535）。初期只有一位簽署者，若以瀏覽器分頁執行，維護者必須固定時間在線，
否則檢查點逾期後即不能開房、條目寫滿後全網拒寫；同一金鑰開在多個分頁還有重複簽署風險。既有決策也不允許可信的常駐 provider。
另外，`config-update` 的收件端已實作，產生端不存在，沒有產生端就無法擴編簽署者或調整任何鏈上設定。

## 考慮過的選項

- 簽署者的瀏覽器分頁：要求固定在線，且同一金鑰在多處分頁時有重複簽署風險，不採納。
- 併入 pinning：pinning 只折疊帳本核心，需要 vendor 全部規則，也會改變 pinning「不提案、不覆核」的定位，不採納。
- 主 repo 內的 node 工具加只放部署設定的公開 repo（採納）。

## 決定

- **外殼位置**：工具程式在主 repo `tools/governance-signer/`，直接使用 `src/ledger` 與完整規則組裝（full-refold），不 vendor；
  瀏覽器與工具共用抽出的 `createLedgerStack` 連線流程。公開 repo `open-4wd-signer` 只放 k8s 與 systemd 部署範本、dispatch-only 部署
  workflow，以 digest 引用主 repo 建置的映像，不建置映像、不含程式與金鑰。工具是治理者的操作工具，不是 provider。
- **打包方式**：以 esbuild 打包成單一 ESM 產物，原生 LevelDB 套件與其依賴閉包隨產物複製；建置資訊（commit、規則版本、三份部署值
  指紋）內嵌並輸出 `build-info.json`。映像由主 repo 的手動觸發 workflow 建置，受 repository 變數閘與預設分支限制，建置前必須通過
  含 N=4 整合測試的完整工具測試，以 digest 引用、不打 latest。
- **信任根**：帳本位址、genesis 時戳與 genesis 簽署者集合不可設定，打包時內嵌三份部署值，執行期以 profile 選用並以與瀏覽器
  相同的驗證；簽署者集合為空一律拒絕啟動。
- **金鑰來源**：治理金鑰專用，與玩家身分、節點身分分開；來源可替換，現有檔案（預設，權限過寬拒絕）、環境變數（讀後刪除、只限
  開發與 CI）與終端機輸入三種。工具記錄來源但不輸出金鑰內容；只有產生金鑰的指令會輸出助記詞。
- **只外連**：工具預設不監聽 libp2p 位址、不當中繼；健康端點只綁本機。
- **單一實例與同步閘**：同一把金鑰同一時間只有一個運作實例。資料目錄以實例鎖加心跳防止雙開，跨主機以心跳過期判斷接手；
  偵測到自身重複簽署或非本行程寫出的自己的票即停止所有自動動作，持久化 halt，只能人工逐字確認解除。投票前必須先過同步閘：
  訂閱者達下限、帳本復原閒置、待定稿索引可讀，之後一段靜默期內帳本無變化；不設逾時放行。
- **管理指令須停常駐實例**：人工釋放鎖定、治理設定匯出與更新、解除 halt 都要先取得同一把實例鎖。
- **config-update 限 N=1**：工具提供 N=1 的設定更新指令（讀入新設定檔、自簽、直接寫 `config-update`），用於擴編與調整參數；
  簽署者多於一位時拒絕，多人收簽另行實作（issue 001539）。
- **規則版本檢查**：帳本狀態的推導規則紀元不在工具內建規則時 halt；工具不以參賽者自報的版本暫停，也不在提案事件加版本欄位。
  工具與 client 在同一切點升級。
- **開發金鑰處理**：公開一把開發用治理金鑰，其 PeerId 只填在 development 部署值；部署檢查與執行期驗證在 private-playtest 與 public
  出現它時報錯，工具同樣拒絕載入。開發時以一鍵啟動指令執行打包產物，瀏覽器只在 development 部署階段放行本機 loopback 的不加密
  WebSocket 撥號。
- 工具的行為以規則 GSIGN-R-001 至 GSIGN-R-008 登錄並由主 repo 的 conformance 測試守住。

現況規格見 [程式架構/governance-signer.md](../程式架構/governance-signer.md)；部署見
[部署資訊/open-4wd-signer.md](../部署資訊/open-4wd-signer.md)。

## 後果與影響

- 新增一個公開 repo 與一份映像建置流程；工具版本與 client 規則版本綁定，新增推導紀元的發版要同時升級工具
  （[流程/升版.md](../流程/升版.md) 第 8 節）。
- pinning 節點 vendored 的帳本必須先接受檢查點控制事件（issue 001488），之後才能在 private-playtest 或 public 運作。
- 同步閘以靜默判斷追上網路，靜默不代表已取得全部條目；最新檢查點的對等比對落地後才能改為比對。
- 人工釋放鎖定本質上是受控的重複簽署，留有營運殘餘風險（issue 001545、001546）。營運文件要求執行前逐一聯絡其他簽署者，確認
  各自只投過一個本體、沒有任何本體已達 quorum，並確認投票對象有誠實簽署者的第一票支撐。
- 擴編到多位簽署者前必須先完成多人收簽（issue 001539）；擴編之後、該功能落地之前無法再調整任何治理設定。
- 治理金鑰以節點專屬 hostPath 掛入，部署 namespace 需放寬 Pod Security，列為容器安全基線的明列例外。
- 與 [D-20260803-06](D-20260803-06-runtime-provider全面社群化.md) 不衝突：工具不提供服務給玩家，簽署權來自金鑰而非角色。
