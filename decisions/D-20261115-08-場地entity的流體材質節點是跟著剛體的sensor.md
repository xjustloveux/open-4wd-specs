# D-20261115-08｜場地 entity 的流體材質節點是跟著剛體的 sensor

> **2026-11-15 關聯追補**：「不可破壞的 entity 可以只有流體節點」已由 [D-20261115-09](D-20261115-09-輸送帶entity至少要有一個非流體節點.md) 修訂為不適用於輸送帶，
> 輸送帶 entity 至少要有一個非流體的節點；其餘不變。

> **2026-11-16 關聯追補**：[D-20261116-01](D-20261116-01-可破壞entity的根節點自身要有幾何.md) 為可破壞 entity
> 增加第三種拒收情況：根節點自身沒有幾何、幾何只在子節點；其餘不變。

## 背景與驅動力

[材質表.md](../材質表.md) 第 6 節規定場地 GLB 內 `is_fluid: true` 的 sub-mesh 永遠是 sensor，車輛零件碰到時觸發
`deploy_behavior`。程式只對不屬於 entity 的流體節點這樣做；屬於 entity 的節點一律被做成包圍盒的實體碰撞體，
流體材質照樣帶入，但不是 sensor，也不觸發效果（issue 001419）。檢核沒有禁止把流體材質指派給 entity。

## 考慮過的選項

- **檢核禁止 entity 使用流體材質**：改動最小，但會動的水窪、油漬這類場地設計就做不出來。不採用。
- **由程式補上，entity 的流體節點也是 sensor**（採納）。
- **改規格，寫明 entity 的流體節點是實體碰撞體**：留下一個會讓作者誤用的組合。不採用。

## 決定

- `physics: default` 的 entity 裡，材質解析為流體的 mesh 節點是 sensor：不建立實體碰撞體，不計入可破壞 entity
  的質量與慣量。材質的回落順序與 collider 相同（節點自身、`materials[]` 覆寫、entity 根節點、場地主材質）。
- sensor 的形狀是節點的 mesh 三角形，與不屬於 entity 的流體區相同。sensor 掛在 entity 的剛體上，隨剛體的位置
  與旋轉移動；`step` 曲線瞬移時一起瞬移。
- 效果取節點材質的 `deploy_behavior` 與 `deploy_params`。
- 不可破壞的 entity 可以只有流體節點而沒有實體碰撞體；有物理的 entity 至少要有一個實體碰撞體或一個流體節點。
  可破壞（`destructible: true`）的 entity 至少要有一個非流體的節點，而且根節點自身不可是流體。質量與慣量只算
  非流體節點，全部都是流體時沒有質量可算；碎片在定稿時由根節點自身的幾何烘焙、不看子節點，根節點自身是
  流體時沒有實體可碎。這兩種情況編輯器檢核與 manifest 推導都拒收。
- entity 被破壞後剛體停用，流體 sensor 從破壞的當下起不再回報接觸，不等下一次物理步進。
- `physics: visual_only` 的 entity 沒有物理，其流體節點沒有效果。
- 場地 PhysicsManifest 的 entity 新增選填欄位 `fluidZones`：每個流體節點一項，記節點名與材質，依節點名排序；
  沒有流體節點時不出現這個欄位。幾何不寫進 manifest，由引擎載入場地時自 GLB 讀出，換到 entity 初始姿態的本機
  座標。重驗時拒收：空陣列、項目帶多餘的鍵、節點名沒有嚴格遞增（含重複）、節點不在 `visualNodes` 裡、節點同時
  是實體碰撞體、材質不是流體、實體碰撞體使用流體材質、`visual_only` 的 entity 帶這個欄位。
- 編輯器對重生點、起點與起跑格的「會動物件活動範圍」警告不把流體節點算進範圍。
- collider 三角形數的計數口徑不變，流體節點的三角形仍計入。

## 後果與影響

- 流體材質的 entity 節點由實體碰撞體改為 sensor，車輛可以穿過並受到流體效果。
- 接觸由物理核心的相交判定回報。測試的一個情境（流體面隨 `linear` 曲線的 entity 連續上下移動、車輛靜止）
  量到：流體面移出車輛的那一步就停止回報，移回車輛內之後的下一步才恢復回報。`step` 曲線瞬移的測試情境
  沒有這個延遲：切換的那一步結束時，兩端的回報就已換過來。
- 沒有流體節點的 entity，manifest 內容不變。
- 專案為 `pre_launch`，不保留舊結構，沒有遷移。
- 現況規格：[材質表.md](../材質表.md) 第 6 節、[建模參數/場地.md](../建模參數/場地.md) 第 9 節。

## 定案紀錄

瞬移，是處理者提出的建議值，使用者沒有提出不同意見。可破壞的 entity 至少要有一個非流體節點、根節點自身不可是流體，
是實作時補上的規則。
