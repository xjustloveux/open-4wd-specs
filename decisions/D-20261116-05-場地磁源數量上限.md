# D-20261116-05｜場地磁源數量上限

## 背景與驅動力

每幀的磁力計算對每個磁源與每個目標各算一次。場地上不屬於 entity 的靜態磁源（PhysicsManifest 的
`track.magnetSources`）與每個 entity 的磁源（entity 的 `magnets`）原本沒有數量上限，只有 entity 數量
（`TRACK_ENTITY_COUNT_MAX`）與磁源強度（`MAGNET_SOURCE_STRENGTH_N_MAX`）有上限（issue 001391）。

## 考慮過的選項

- **靜態磁源與每個 entity 的磁源分別設上限**（採納）：靜態 64 個、每個 entity 8 個。
- **只設一個總數上限**（靜態加所有 entity 的磁源合計，例如 256 個）：作者分配較自由，但單一 entity 可以吃掉全部額度。
- **不設上限**：維持現狀，每幀計算量沒有上界。

## 決定

- 新增協定常數 `TRACK_STATIC_MAGNET_SOURCE_COUNT_MAX = 64`、`TRACK_ENTITY_MAGNET_SOURCE_COUNT_MAX = 8`。
- 一個 `source` 材質且適用強度為正的 mesh 節點算一個磁源；`visual_only` 的 entity 沒有磁源，不計。
- 編輯器檢核、manifest 推導（定稿與首次準入）與 PhysicsManifest 結構驗證都拒收超限。哪些節點是磁源由烘焙、
  推導與編輯器檢核共用同一份判定。

## 後果與影響

- 加上 entity 數量上限 100，每幀場地磁源最多 864 個（64 加 100 個 entity 各 8 個）。
- 專案為 `pre_launch`，不需相容超限的舊場地。
- 現況規格：[建模參數/場地.md](../建模參數/場地.md) 第 9.4 節、[程式參數/protocol.md](../程式參數/protocol.md)。

## 定案紀錄

2026-11-16 處理 issue 001391 時由使用者裁決：採分別設上限，數值依處理者建議取 64 與 8。
