# D-20261124-04｜條目有效性以檢查點切面與確定性時鐘判定

## 背景與驅動力

帳本條目原本只要接到任一 head 或檢查點邊界就算相連，而相連的判斷依據是本機 index。同一個執行期的 index 裡還有
檢查點之前的條目，重啟後的 index 只由邊界之後的條目重建，所以同一筆晚到條目在重啟前後得到不同結論；相連判定也沒有
逐一檢查條目的每個 parent，節點之間對同一條目的結論與可用性可能不一致（issue 001511）。條目時鐘與 `clock.id` 沒有與
parent 及簽章金鑰比對（issue 001522）。這兩項都讓條目是否被收下、以及在全序中的位置，不完全由 DAG 與檢查點決定。

## 考慮過的選項

- 區間走訪改為真正的差集（issue 001511 乙案）：裁剪過條目的節點無法證明某個 parent 已被涵蓋，各節點結論仍會不同，不採納。
- 時鐘只要求嚴格大於 parent 並加上界：寫入者仍可在上界內挑選時鐘、逼近上界，不採納。
- 檢查點切面、時鐘恰等於 parent 最大值加 1、`clock.id` 綁條目簽章金鑰（採納）。
- 寫入端在已有候選檢查點時只取候選閉包內的 heads 當 parent，以減少採納後的孤兒：多節點模擬（以 tick 計延遲的記憶體網路，
  只代表檢查點前後的窗口）中，N=1 有晚到條目時窗口內約 67% 的業務寫入成為孤兒，N=4 為 48%–78%；此政策在 N=4 估計可避免
  約一半（上限估計），對 N=1 與離線後上線無效，而所有情境不靠它也收斂，每筆重新建立約 0.1–0.3 秒工作量（偶爾約 1 秒）。
  暫不實作，待 private-playtest 的實測再議。

## 決定

- **切面**：最新已採納檢查點 K 的 `log_head_cids` 加上「每一個 parent 都在集合內、時鐘合規」的條目，反覆擴張得到切面 S。
  條目有效若且唯若每個 parent 都在 S；只要有一個 parent 在切面之前就拒絕。尚無檢查點或 K 的 heads 為空時從創世起算，
  任何時鐘為 1 的根都有效；有非空 heads 的檢查點之後，根條目以 `stale-parent` 拒絕。遠端 join 與本機提交用同一個判定，
  能否加入 S 的判定不讀 index、不依到達順序或是否重啟（index 只用於走訪祖先時的提早拒絕與整理）。
- **孤兒**：本機已有、但不在 S 也不在 K 涵蓋範圍的條目。孤兒不在視圖、不能當 parent，從 heads 與 index 移除，可被淘汰；
  heads 恆等於 S 的極大元素。
- **時鐘與 clock id**：時鐘恰等於 parent 最大值加 1，沒有 parent 為 1；`clock.id` 等於條目簽章金鑰 `key`，`key` 等於
  條目 identity 的公鑰。
- **同一規則套用到開庫重建、涵蓋範圍還原與邊界推進**：重建不合格的條目成為孤兒、不使開庫失敗；涵蓋範圍內時鐘違規即開庫失敗，
  不遷移既有本機資料（專案在 pre_launch）；推進邊界要求新檢查點的 heads 都在目前的 S；走訪碰到切面外的條目即以確定的錯誤停下。
- **被拒寫入重新建立**：本機提交以 `stale-parent` 被拒時，寫入器以同一事件、目前 heads 重新建立條目並重付准入工作量，
  新紀錄先持久化再刪舊紀錄，每個寫入意圖最多 3 次。自己已提交、在本執行期成為孤兒的條目同樣重新建立；重啟之後才成為孤兒者
  不重新建立。待送出紀錄格式本決策不改。
- **固定 Orbit 寫入者身分**：每個裝置、每條鏈一個，存於該鏈的檢查點 control storage，不從玩家或治理金鑰推導；瀏覽器與
  治理簽署工具相同，簽署工具不再在資料目錄另存 id 檔。動態 genesis 的暫時開庫不帶固定 id。
- 條目 wire 不變：誠實寫入端本來就寫出符合規則的時鐘與 `clock.id`。

現況規格：[ledger-checkpoint.md](../程式架構/ledger-checkpoint.md) 第 4 節（LEDGER-R-045、LEDGER-R-107、LEDGER-R-108）、
[ledger-admission.md](../程式架構/ledger-admission.md) 第 1 節（LEDGER-R-109）、[ledger.md](../程式架構/ledger.md) 第 10 節。

## 後果與影響

- 採納窗口內合併了晚到條目的寫入會成為孤兒，需要重新建立並重付工作量；寫入延遲與耗電在檢查點前後增加。
- 切面不決定同一檢查點間隔內事件的先後：依賴先到先贏的領域規則仍須各自處理（issue 001529），窗口縮到一個檢查點間隔但不歸零。
- 重新建立的事件在尚未採納該檢查點的節點上可能與原條目短暫同時有效，採納後收斂；事件通知的重複另案處理（issue 001552）。
- 自有條目在重啟之後才成為孤兒時，該事件不會自動重送；以「已提交、尚未被檢查點涵蓋的事件保留至涵蓋」補上，併入待送出紀錄
  的改版（issue 001513）。
- pinning 節點 vendored 的帳本必須同步切面、時鐘與走訪規則（issue 001488），否則會保留並交換孤兒 heads；排在本決策落地後、
  private-playtest 之前。
- 修訂 [D-20261123-03](D-20261123-03-帳本讀取以本機保留範圍為界.md)：本機保留範圍的「目前 heads」改為切面 S 的極大元素，
  孤兒雖在本機但不屬保留範圍。修訂 [D-20260719-01](D-20260719-01-LedgerAdmission-v1.md)：durable outbox 的重送對被切面拒絕的
  條目改為以同一事件重新建立（條目 CID 不同），業務層仍以既有冪等規則處理同一事件。

## 定案紀錄

2026-11-24 由使用者裁決採切面、時鐘恰等於與 `clock.id` 綁簽章金鑰；2026-11-25 依實作計畫的待裁決題全部照建議（每個 parent
都必須在 S、孤兒定義、自有孤兒重新建立、`key` 綁 identity、固定 Orbit id 存於 control storage、待送出紀錄格式留待後續、
既有本機資料不遷移），並接受尚無非空檢查點時多根有效、重啟後才成為孤兒者不重新建立；2026-11-26 裁決寫入端 parent
選擇暫不實作。
