# D-20261123-04｜帳本 recovery 失敗後依退避重試

> **2026-11-24 關聯追補**：決定段第一條末句分號後的部分「checkpoint 採納或定稿後的重建是另一個佇列工作，不經
> single-flight，失敗不計入退避」中失敗不計入退避的部分，已由
> [D-20261124-06](D-20261124-06-定稿與採納後的重建失敗計入退避.md) 修訂為失敗時標記 ingest failure、依退避表排重試並計入失敗次數（已有待執行的重試時不改變它、也不計入）。

## 背景與驅動力

條目已寫入 log 但增量折疊失敗時，帳本標記 ingest failure 並做一次全量重建；恢復完成前業務讀取與寫入都拒絕
（[ledger-checkpoint.md](../程式架構/ledger-checkpoint.md) LEDGER-R-048）。這次重建若也失敗，沒有任何路徑會
再試一次，節點只能關閉重開（issue 001503）。會讓重建失敗的原因多數是暫時的，例如儲存層讀取失敗、checkpoint
的狀態塊一時取不到；有些在下一個 checkpoint 被採納後就不再成立。不過 ingest failure 期間到達的 checkpoint 公告
目前不會被送進採納流程，除非公告在失敗前已進入採納流程或由啟動掃描送入，否則這類失敗在同一個 runtime 內等
不到採納；這是已知缺口，另案處理。

啟動時的 checkpoint 公告掃描在背景失敗時，原本借用同一個 ingest failure 標記，但全量重建並不會重新掃描，
這個標記也就沒有任何路徑能清除。

## 考慮過的選項

- **三種時機觸發重試，並以退避限制頻率（採用）**：失敗期間有新條目到達、checkpoint 採納或定稿後的重建、
  退避計時器到期。暫時性原因在原因消失後自動恢復，安靜的網路上也不必等下一筆條目。
- **只在事件到達時重試，不設計時器**：沒有新條目的節點在暫時性失敗後會一直停在失敗狀態。不採用。
- **只在 checkpoint 採納後的重建成功時清除**：只能解決採納後就不再成立的原因，其餘仍須重開。不採用。

## 決定

- 三種時機的重建都是狀態佇列中的單一工作，不與其他狀態變更並行。新條目到達與退避計時器到期共用同一個
  single-flight 排程，失敗計入退避；checkpoint 採納或定稿後的重建是另一個佇列工作，不經 single-flight，失敗
  不計入退避。
- 退避間隔依連續失敗次數為 1 秒、5 秒、30 秒、2 分鐘，之後固定 5 分鐘，不設總次數上限。新條目觸發的重試
  不得早於目前的退避間隔。
- 任何一次成功的重建都在同一個佇列工作內清除 ingest failure、補發積欠的通知並把退避歸零；補發通知時訂閱者
  拋出例外視同該次重建失敗。
- 啟動掃描在背景失敗時記為獨立的狀態並依同一組退避間隔自行重掃；前景等待期間失敗仍讓開啟失敗。
- 計時器在帳本關閉與開啟失敗時清除，回呼只對排定它的那一次開啟有效。
- 失敗期間對外行為不變；另提供可讀的復原狀態（階段、已失敗並排定重試的重建次數、上次錯誤的摘要）給介面顯示；
  進入失敗後立即執行的第一次重建若失敗也計入次數。

## 後果與影響

- 純本機行為，不涉共識；退避間隔是本機排程政策，與其他帳本本機常數一樣定義在帳本模組，並登錄於
  [protocol.md](../程式參數/protocol.md) 的參數表。
- 永久性原因（例如狀態塊內容損壞）會以 5 分鐘間隔持續重試而不會成功；介面可依復原狀態提示使用者。
- 現況規格：[ledger-checkpoint.md](../程式架構/ledger-checkpoint.md)、[ledger.md](../程式架構/ledger.md)。

## 定案紀錄

2026-11-23 由使用者裁決：採三種時機重試、成功即清除、啟動掃描失敗改用獨立狀態的方案。
