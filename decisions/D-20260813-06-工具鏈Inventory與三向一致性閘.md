# D-20260813-06｜工具鏈 Inventory 與三向一致性閘

## 背景與驅動力

正式驗證入口分散在 package scripts、文件與 workflows；有些 command 已在 CI 執行，有些仍是
本機 opt-in 或因外部 bytes 不在 checkout 而明示 skip。逐檔抄錄所有 scripts 會快速過時，只檢
package 與文件則無法發現 workflow condition 或 compound subcommand 漂移。

## 考慮過的選項

- 維持分散文件，由 review 人工同步：成本最低，但 current／target 容易混寫。
- 在總架構檔逐一列出 scripts：入口集中，卻複製 package 與 workflow 細節。
- 獨立 toolchain inventory，程式架構只給定位，package／docs／workflow 建立三向 gate：採納。

## 決定

[程式架構](../程式架構.md) 只說明工具鏈分層並連到
[toolchain](../程式架構/toolchain.md)；後者列正式命令、compound 子命令、canon owner、目前執行
證據、目標狀態與 workflow condition。[testing](../程式架構/testing.md) 保存測試 profile 與 opt-in
旗標語意。機器檢查同時解析 package scripts、文件 inventory 與 workflows，任一正式入口缺列、
文件宣稱與 CI condition 不符或反向孤兒都失敗。外部 authoring／resume 缺必要 bytes 時只能明示
skip，不得記為 pass。

## 後果與影響

工具鏈有一個可閱讀 inventory，但執行真相仍由 package 與 workflow 原始碼提供並經三向 join 驗證。
新增、改名或改 condition 必須同步相應文件；不需把所有內部 helper 或空目錄提升成正式入口。
