# D-20260725-02｜首次公開直接使用正式域名

## 背景與驅動力

正式域名 `open4wd.org` 已購入，主 repo 在開發前期保持 private，期間不會發布 GitHub
Pages。因尚不存在公開 production origin、舊 public client、搜尋索引或 origin-bound 玩家
資料，首次公開與 [D-20260704-03](D-20260704-03-域名遷移機制.md) 處理的「既有公開
origin 遷移」條件不同。

## 考慮過的選項

- 先發布 `github.io/open-4wd`，再遷移至正式域名：會人為建立第二個公開 origin，平白
  引入 major 過渡、301 herding、搜尋索引與 origin storage 遷移成本。
- private 期間只做本機／私有驗證，第一次公開即綁定正式域名（採納）。

## 決定

- private 期間不發布 GitHub Pages；第一個公開 production origin 直接使用
  `https://open4wd.org/`。
- 正式 build 使用 root base path (`/`)；`xjustloveux.github.io/open-4wd/` 只保留為
  顯式 preview／災難回復 hosting target，不是 canonical origin。
- 首次公開只執行 DNS／TLS、PWA scope、canonical URL、deep link、`/version.json`
  與部署服務 smoke；不執行 30 天 banner、major 過渡或 301 herding。
- [D-20260704-03](D-20260704-03-域名遷移機制.md) 保持原樣，繼續作為未來已有公開
  origin 時的遷移裁決。

## 後果與影響

首次公開與日後 origin 遷移正式分流；部署組態不再需要
`CUSTOM_DOMAIN_FALLBACK`。GitHub Pages workflow 在 private 期間不發布，轉 public
並通過正式部署 gate 後才以 custom-domain root build 上線。現況權威見
[部署資訊.md](../部署資訊.md)。
