# D-20261123-01｜重新檢舉的時戳須晚於既有案錄

## 背景與驅動力

檢舉在抽籤前撤回、流局或過期後，同一檢舉者可以對同一對象重新檢舉。檢舉案的案件 id 由檢舉者、檢舉時戳與對象
合成，仲裁結果以案件 id 冪等。帳本的單簽事件沒有事件層的去重，同一筆已簽的檢舉事件可以再次進入帳本；檢舉的守門
原本只看既有案錄的狀態，不比較時戳，於是已撤回或已流局的那筆檢舉事件再次進入時會被當成一次重新檢舉，以同一個
案件 id 覆寫案錄。撤回因此失效；流局的案件 id 已有結果，覆寫後的案錄無法再結案（issue 001494）。

## 考慮過的選項

- **重新檢舉的時戳必須晚於既有案錄的檢舉時戳（採用）**：放在收件驗證與 fold 共用的檢舉守門。一條條件同時涵蓋
  撤回後、流局後與時戳更早的舊事件；判定只讀既有案錄，不增加帳本狀態。正常的重新檢舉是一筆新簽的事件、帶新的
  時戳，不受影響。
- **對所有單簽事件做事件摘要去重**：通用，但帳本狀態要保存已處理事件的摘要，狀態量隨事件數成長，並牽動每一種
  單簽事件的守門與檢查點內容，屬於較大的設計變更。不為這個問題採用。
- **只在案件 id 已有結果時拒絕重新開案**：涵蓋流局後的情況，但撤回的案件 id 沒有結果，涵蓋不到。不採用。

## 決定

- 同一檢舉者對同一對象已有案錄時，新的檢舉事件時戳必須晚於該案錄的檢舉時戳；否則收件拒收、fold 不改動狀態。
- 這個條件屬於檢舉守門的一部分，收件驗證與 fold 使用同一個判定。
- 不同檢舉者之間不比較時戳；其餘重新檢舉的條件（已撤回、流局或過期才可再告）不變。

## 後果與影響

- 每個檢舉案的案件 id 至多開案一次；撤回與仲裁結果不會因為舊的檢舉事件再次進入帳本而失效。
- 重新檢舉的時戳若不晚於前一筆（例如裝置時鐘被調回較早的時間）會被拒收，需以正確的時鐘重新送出。
- 共識規則改變（哪些檢舉事件會開案）。專案尚未公開，沒有已發布的資料受影響。
- 其他單簽事件型別沒有納入這次決定。

## 定案紀錄

2026-11-23 由使用者裁決：採用時戳條件，不採用對所有單簽事件做摘要去重。
