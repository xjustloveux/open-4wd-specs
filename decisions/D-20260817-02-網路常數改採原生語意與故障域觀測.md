# D-20260817-02｜網路常數改採原生語意與故障域觀測

## 背景與驅動力

網路常數表混合了 libp2p 原生選項、尚未定義映射的分數概念與 provider 可得性目標。名稱雖像 runtime 設定，實際上沒有 production consumer；其中兩個 peer-score 名稱更與目前 GossipSub API 的三層門檻不一致，容易讓文件與實作各自形成一套政策。

## 考慮過的選項

- 保留舊名稱並在 adapter 猜測轉換：會把錯誤語意固定成永久相容面，且 decay 沒有可驗證公式（未採）。
- 將三份帳本副本傳入 OrbitDB：目前 runtime 沒有對應選項，也無法表達跨營運者故障域（未採）。
- 增加 strict／minor-compatible 模式：沒有第二套已核准行為，只會建立無效開關（未採）。
- 採 libp2p 原生欄位，另把 provider 數量定位成非阻擋觀測（採納）。

## 決定

DHT 與 GossipSub 由 adapter 明示傳入目前套件的原生 query-self、mesh、heartbeat 與 gossip／publish／graylist 門檻。帳本服務的三個獨立 provider 故障域改為 best-effort UI／營運觀測，bootstrap 或健康 pinning 不足時只提示，仍允許離線或單一節點啟動。版本相容性不再設模式常數，由既有檢查函式直接執行 client major 相同且其餘版本欄位全等。

## 後果與影響

常數名稱重新對齊實際 consumer，不再暗示不存在的 OrbitDB replication 或 peer-score reject／decay 行為。設定頁會揭露目前可觀測故障域，但數值不構成持續供應、資料留存或恢復保證；現行權威見 [程式參數.md](../程式參數.md)、[部署資訊.md](../部署資訊.md) 與 [程式架構/peer-discovery.md](../程式架構/peer-discovery.md)。
