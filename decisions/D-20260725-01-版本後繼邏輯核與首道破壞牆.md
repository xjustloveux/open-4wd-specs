# D-20260725-01｜版本後繼邏輯核先落地、第一道破壞牆原子啟用

## 背景與驅動力

[D-20260528-02](D-20260528-02-B軸schema版本系統.md) 與 [D-20260703-02](D-20260703-02-B軸掛client-major與升級通道.md) 已定義版本後繼與六條收件條件，但主程式尚未有真實破壞牆。規則追溯發現若等到首道牆才一次補齊 fold、血緣與經濟映射，最容易把「同一血緣節點」誤作新 fork 層；反過來，現在直接開放事件持久化又會讓尚無 production descriptor 的半套協議進入帳本。

## 考慮過的選項

- 等第一道破壞牆再整批實作：短期改動最少，但規則核心與跨域聚合沒有可執行證據。
- 現在即開放 `asset-version-upgrade`：可端到端行走，但 production 尚無合法 descriptor，事件 admission 與 protocol 契約沒有可接受的真實輸入。
- 先落地 dormant 邏輯核與測試 descriptor，首道牆再原子啟用（採納）。

## 決定

- 先實作 descriptor contract、fold guard、atomic reducer、後繼邊與 lineage-node 正規化；royalty、評分、使用量及 fork ancestors 一律以血緣節點聚合，具體來源 CID 仍保留供稽核。
- production descriptor catalog 在首道真實破壞牆前保持空；`asset-version-upgrade` 不加入目前事件 allowlist，現行 admission 繼續拒絕。測試以獨立 descriptor 證明行為，不把測試牆冒充已部署歷史。
- 可序列化 descriptor metadata 為單一權威，生成公開 manifest 並以 stale check 守門；migration 函式由 TypeScript binding 承載，CI 逐筆比對兩側 projection，避免只更新其中一邊。
- 第一道破壞牆必須依 [升版.md](../流程/升版.md) 同批完成 descriptor／雙向 migration、live content validation、persistence admission、replay／checkpoint／protocol 相容性與測試；不得只打開事件 allowlist。
- 公開凍結前 checkpoint 與相關 baseline 版本維持 `1`。只有真實不相容格式已存在且需要區隔時才升版，不為未部署的 v2/v3 製造虛假歷史。

## 後果與影響

版本後繼規則現在可在不擴大 production 協議面的前提下被完整測試；首道破壞牆仍是一個明確、不可拆分的發版工作包。現況權威見 [版本規範.md](../版本規範.md)、[資料系統.md](../資料系統.md) 與 [程式架構/ledger.md](../程式架構/ledger.md)。
