# D-20260817-03｜比賽執行常數與賽前窄路警告收斂

## 背景與驅動力

物理與賽事常數同時混有真正漏接的倒數節拍、已有 CI 消費的最壞情況界標、只重述現況的零值，以及沒有超限處置的碰撞對數。場地雖已烘焙最窄路徑，正式賽事也尚未把它轉成玩家可見的相容性提示。

## 考慮過的選項

- 為每個常數製造 runtime 讀取：會重複 invariant gate，且無法替碰撞對超限發明決定性語意（未採）。
- 保留名目 16 ms 與零 input delay 作文件常數：兩者都不控制行為，反而可能成為第二權威（未採）。
- 保留有實際不變式 consumer 的界標，只接入倒數與窄路警告並移除其餘宣告（採納）。

## 決定

正式倒數使用 gameplay 所有的 1000 ms 節拍。物理 dt 唯一機器權威維持固定幀率的精確倒數，純 rollback 不另加 input delay；未定義超限結果的碰撞對數不列常數。rollback 邊界與整場 rigid-body 預算保留為 CI invariant。場地 admission 將有效 `auto_narrowest_path_m` 投影成 typed `TrackPhysicsManifest.narrowestPathM`，race runtime 不重新解析 raw GLB extras。賽前以 admitted 場地最窄寬度比較本車各零件 mount 後 AABB 聯集寬度與安全餘裕，只有超寬時發布本機警告，仍允許開始。

## 後果與影響

比賽控制時序不再依賴 UI 動畫常數，也不再保存無行為的顯示或零值常數。窄路資料缺席、無效或車輛量測不可得時保持靜默；提示不進 admission、物理、wire 或共識。現行權威見 [程式參數.md](../程式參數.md)、[賽內機制.md](../賽內機制.md) 與 [流程/比賽進行.md](../流程/比賽進行.md)。
