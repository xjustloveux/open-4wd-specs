# D-20261112-03｜音訊共用單一 Context 與總輸出限幅

## 背景與驅動力

issue 001313：SFX、世界音、BGM 三個引擎各有自己的 `AudioContext`，鏈上只有 gain。以預設音量（master 80、sfx 100、
bgm 80）和音檔峰值推算，BGM 約 0.57、一個單發音效約 0.42，兩者同時出現就接近滿刻度，再加任何循環聲源就超過。
世界音在同一個 context 內多聲源相加也可能超過 1.0。跨 context 的總和由作業系統混音，是否破音取決於平台，
應用程式無法控制。

## 考慮過的選項

- **甲：三個引擎共用單一 `AudioContext`，總輸出前放一個限幅器**：所有聲音的總和都受保護，也少開兩個 context；
  要改三個引擎的組裝與恢復流程。
- **乙：維持三個 context，只在世界音與 SFX 鏈各放一個限幅器**：改動小；BGM 與另外兩路的總和仍不受保護。
- **丙：不加限幅器，降低預設音量或音檔峰值**：最簡單；整體音量變小，極端疊加仍可能超過。

限幅器使用 `DynamicsCompressorNode`。它會依門檻與比例自動加上補償增益，把未達門檻的聲音也放大；規格把這個增益
定為「滿刻度輸入經壓縮曲線後衰減量」的 0.6 次方倒數，所以可以用一個固定 gain 精確抵銷。

門檻以 Chromium 的 `OfflineAudioContext` 比較（`default` 主題音檔，各算 6 秒、統計略過前 0.5 秒，聲源直接相加、
不含空間化與距離衰減）：

| 情境                                                         | 不限幅            | 門檻 −1 dB        | 門檻 −3 dB      |
| ------------------------------------------------------------ | ----------------- | ----------------- | --------------- |
| 極端：BGM、8 個同相馬達聲、每秒一次重碰撞，音量全部 1.0      | 峰值 2.008，34044 | 峰值 1.086，290   | 峰值 0.898，0   |
| 預設音量：BGM 0.64、8 個起始位置錯開的馬達聲與重碰撞各 0.8   | 峰值 0.691，0     | 與不限幅相同      | 與不限幅相同    |
| 平常：BGM 0.64、一個馬達聲 0.24、一次重碰撞 0.4              | 峰值 0.410，0     | 與不限幅相同      | 與不限幅相同    |

每格第二個數字是絕對值超過 1.0 的取樣數。比例 20、knee 0、起音 3 毫秒、釋放 0.25 秒；補償增益已抵銷。

## 決定

採甲。

- 三個引擎共用 `src/audio-system/audio-output.ts` 建立的單一 `AudioContext`（要求 48 kHz，平台不接受時用裝置預設）。
- 共用輸出為 `input → DynamicsCompressorNode → 補償增益 → destination`；引擎的 gain 鏈只能接到 input。
- 限幅參數：門檻 −3 dB、比例 20、knee 0、起音 0.003 秒、釋放 0.25 秒，定義在 `UI.audio`。門檻 −1 dB 在極端情境
  仍有 290 個取樣超過滿刻度，所以取 −3 dB。
- context 的恢復集中在共用輸出：`running`／`closed` 略過，進行中的恢復不重複發出。

## 後果與影響

- 極端情境下峰值由 2.008 壓到 0.898，沒有取樣超過滿刻度；預設音量與平常情境的輸出與不限幅時相同
  （峰值相同，RMS 以 dB 計到小數兩位相同）。以上只在 Chromium、以上述三個情境量測，其他瀏覽器的壓縮器實作沒有量測。
- BGM 單獨播放且主音量與 BGM 音量都調到 100 時，音檔峰值最高 −1 dBFS，高於 −3 dB 門檻，最響的峰值會被壓低；
  預設音量下 BGM 峰值約 0.57，不會觸發。
- 壓縮器會帶來數毫秒的固定延遲，所有聲音一起延後；沒有量測實際延遲。
- 引擎的單元測試以假 context 檢查每條訊號路徑都經過限幅器才到 destination。
- 現況規格：[程式架構/audio-system.md](../程式架構/audio-system.md) 第 5 節、[程式參數/ui.md](../程式參數/ui.md) 第 13 節。
- 與既有決策的關係：amends [D-20261112-02](D-20261112-02-BGM改以Web-Audio-buffer循環播放.md) 決定中「BGM 使用自己的
  `AudioContext`」一項；BGM 以 buffer 循環播放的做法不變。

## 定案紀錄

2026-11-12 查證 issue 001313 後提出甲、乙、丙三個做法並建議甲，使用者裁決依建議。實作時先以門檻 −1 dB 量測，
極端情境仍有取樣超過滿刻度，改為 −3 dB。
