# D-20261030-01｜公版零件程序化交付

## 背景與驅動力

[D-20261022-01](D-20261022-01-公版場地程序化交付與零件維持延後.md) 交付三個程序化公版場地時，零件仍在重做、權利證據未齊，所以把 `public/assets/builtin-delivery.json` 的 `parts` 定為 `deferred-prelaunch`，manifest 的 `decision` 欄位也指向該決策。交付狀態的 schema 編號後來由 [D-20261029-05](D-20261029-05-builtin交付schema重新編號為1.md) 改回 1，其餘內容不變。

此後 24 顆公版零件由維護者委派的 coding agent 以 Blender 4.5.5 LTS 的 `bpy`／`bmesh` 原語程序化從零建立，貼圖由 numpy 以固定種子的程序雜訊產生。生成器快照、生成說明與來源說明放在 specs 的 `release-input/parts/`，可逐位元重現 authoring GLB；出貨檔經正式 canonical finalizer、Draco 與 KTX2 產生，24 顆 findings 皆為 0。製作時只從 60 分及格版本讀取 Mount 位置、整體尺寸與根節點材質作介面錨點，並以參考渲染圖與維護者的原始概念圖量取剪影與比例；沒有繼承任何頂點、面、UV、貼圖像素或節點結構。三個公版場地同樣由程序化生成器從零建立，只以既有參考圖與 60 分及格版本作版面與風格的視覺參考。

2026-10-29 修 issue 001062 時發現兩側不一致：manifest 的 `kinds.parts.state` 已是 `delivered`，`public/assets/builtin/parts/PROVENANCE.md` 六節俱全並記載維護者 2026-10-24 核准交付計畫，但同檔仍寫「權利內容仍待維護者最終審閱」；canon [程式架構/builtin-assets.md](../程式架構/builtin-assets.md) 仍寫 `parts` 為 `deferred-prelaunch`，管線段也仍寫「零件由 Tripo3D 生成高模」（issue 001132）。場地的 PROVENANCE 同樣留有兩句待審。

2026-10-30 維護者裁決：公版零件與公版場地都是 agent 程序化從零生成，不存在權利問題，兩類的權利審閱都已完成；零件維持 `delivered`。

## 考慮過的選項

- **確認交付：canon 改寫為兩類皆已交付，兩類 PROVENANCE 的待審句改為核准紀錄（採納）**。與 manifest、出貨 bytes 與既有核准紀錄一致。
- 交付狀態退回 `deferred-prelaunch`：與已完成的生成、finalizer 驗證與逐類核准不符，且會讓需要整車的測試繼續授權 skip（否決）。

## 決定

- `public/assets/builtin-delivery.json` 的 `kinds.parts.state` 維持 `delivered`；`kinds.tracks` 本就是 `delivered`，兩類現已全部交付。manifest 形狀與 `schemaVersion: 1` 不變。
- manifest 的 `decision` 欄位改為 `D-20261030-01`；`scripts/builtin-assets/delivery-state.mjs` 的 `DECISION` 常數與 `delivery-state.d.mts` 的對應字面型別同步改為本決策。交付權威此後指向本決策；分類型交付模型本身仍是 D-20261022-01 定的。
- 公版零件與公版場地的權利審閱都已完成：兩者來源都是維護者委派的程序化生成器，從零建立幾何與貼圖；對 60 分及格版本與參考圖的使用只取量測值或作視覺參考與生成後對照，不構成權利關聯。維護者於 2026-10-30 核准。
- 下列四份 PROVENANCE 中「權利內容仍待維護者最終審閱」與「此參考使用是否構成任何權利關聯屬法律判斷，待維護者審閱」兩類句子，改為記錄本次核准（2026-10-30、維護者核准、引用本決策）。六節結構不變：
  - main：`public/assets/builtin/parts/PROVENANCE.md`、`public/assets/builtin/tracks/PROVENANCE.md`。
  - specs：`release-input/parts/PROVENANCE.md`、`release-input/tracks/PROVENANCE.md`。
- 各 PROVENANCE 開頭的「Release tag：待發布後填入」維持原文：authoring-source immutable Release 延後發布，由 issue 001141 追蹤，不屬權利審閱。依 D-20261022-01，main 採用新 authoring 來源前仍須由維護者發布該 Release 並更新 dependency lock。
- canon [程式架構/builtin-assets.md](../程式架構/builtin-assets.md) 改寫現況：兩類皆為 `delivered`、交付權威的 `decision` 為本決策；管線段改述零件與場地一樣由受版控的 Blender 程序化生成器從零建立、生成器快照與 authoring GLB 隨 authoring-source Release 保存，再走同一 finalizer、Draco＋KTX2 與 per-file 上限，刪除「零件由 Tripo3D 生成高模」。同段引用 [美術資源/提示詞/零件參考圖.md](../美術資源/提示詞/零件參考圖.md) 的「生成階段高模建議值」屬 Tripo 管線，是否保留由實作時一併檢視，不屬本決策。
- main `README.md`「內建 GLB 資產」一節改述兩類皆已交付。
- D-20261022-01 的其餘決定（分類型交付、strict／release 兩類都要 `delivered`、需要整車與只需場地的測試分別要求、256 KiB root extras 上限、`authoring-text.zip`）全部不變。
