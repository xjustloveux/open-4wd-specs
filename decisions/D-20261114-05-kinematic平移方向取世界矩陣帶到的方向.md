# D-20261114-05｜kinematic 平移方向取世界矩陣帶到的方向

## 背景與驅動力

`kinematic_move` 的 `amplitude_m` 以節點初始姿態的 local frame 宣告。issue 001392：比賽端用世界矩陣
近似出來的旋轉（各基底欄正規化，行列式為負時把第三欄取反）轉動幅度。祖先帶鏡射時，這個近似讓部分方向
與節點實際被世界矩陣帶到的方向相反；祖先帶非等比縮放再接旋轉時方向也有偏差。編輯器預覽由 scene graph
合成父層變換，顯示的是實際被帶到的方向，兩邊不一致。在建模軟體把半邊場地鏡射複製是常見做法。

## 考慮過的選項

- **以世界矩陣實際帶到的方向為準，比賽端改算法**（採納）：鏡射出來的物件往鏡射後的方向移動，與畫面一致。
- **以比賽原本的近似為準，預覽改成套用同一個近似**：改動只在編輯器，但鏡射出來的物件往反方向移動。
- **拒收鏡射或剪切祖先下的 `kinematic_move`**：兩邊都不必改，但擋掉鏡射複製的做法。

## 決定

- 平移的世界向量：先以節點自身的旋轉轉動 `amplitude_m`，再乘上父節點世界矩陣的線性部分，取其方向；
  長度是 `amplitude_m` 的長度（世界公尺）。節點自身的縮放不參與。
- 節點自身的旋轉取 glTF 節點的 `rotation`，不是單位長時先正規化，四個分量全為 0 時當成沒有旋轉。
  以 `matrix` 宣告的節點取各基底欄正規化後的旋轉；行列式為負時把負號歸給 X 軸縮放（先把第一基底欄
  取反），與編輯器載入節點時分解 `matrix` 的方式相同。
- 同一個本機變換以 TRS 宣告或以 `matrix` 宣告，自身旋轉的取法不同，平移方向可能不同。例如本機變換
  是 Z 軸縮放 -1：以 `scale` 宣告時幅度 +X 的方向不變，以 `matrix` 宣告時分解成繞 Y 轉 180 度加 X 軸
  縮放 -1，幅度 +X 的方向相反。
- 父節點的世界矩陣讓這個方向退化（某軸縮放為 0 或帶非有限值）時 entity 拒收。
- 編輯器預覽與比賽的推導共用同一個算式。
- 旋轉（`rotation_axis`）在鏡射與非等比縮放下的方向不在這個決定的範圍內。

## 後果與影響

- 這是共識行為變更：祖先帶鏡射或非等比縮放、或節點自身帶負縮放的 `kinematic_move`，比賽中的平移
  方向可能改變，是否改變視變換與幅度的方向而定。例如節點自身沒有旋轉、父層縮放 (2, 2, 3) 時幅度 (1, 1, 0) 的方向
  不變、幅度 (1, 0, 1) 的方向改變。
- manifest 內的幅度是解出來的值：執行期以初始姿態的旋轉轉動幅度，那個旋轉由世界矩陣近似而來，寫入的
  幅度要讓執行期轉動後得到上述世界向量。解出來的值與宣告值逐分量的差不超過
  1e-9 × max(1, 幅度長度) 時，manifest 原樣保留宣告值。
- 寫入值與宣告值不同的例子：沒有祖先、自身縮放 (-1, 1, 1)、宣告 (0, 0, 2) 時寫入 (0, 0, -2)。
  `rotation` 的長度偏離 1 時解出來的值可能偏離宣告值；只有單精度的 `rotation` 配 2 公尺以上的幅度時，
  實測多數寫入值與宣告值不同。
- 寫入解出來的值時，世界位移是上述世界向量。保留宣告值時，世界位移與上述世界向量可以有容差量級的
  差；幅度本身小於容差時方向可能相反，例如自身縮放
  (-1, 1, 1)、宣告 (0, 0, 5e-10) 時比賽的位移是 (0, 0, -5e-10)、預覽是 (0, 0, 5e-10)。
- 三個公版場地沒有 `kinematic_move`，不受影響。
- 祖先帶非等比縮放、節點自身有旋轉時，預覽的方向也跟著改變：原本預覽把父層縮放逐軸除掉，現在方向
  反映父層的非等比縮放。
- 現況規格：[建模參數/場地.md](../建模參數/場地.md) 第 9.2 節。

## 定案紀錄

2026-11-14 使用者裁決鏡射下的位移方向以編輯器預覽顯示的方向為準。
