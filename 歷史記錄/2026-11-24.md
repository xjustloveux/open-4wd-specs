## 重大重構里程碑

### 2026-11-24 ─ deriveStateAt 的目標限於檢查點本身與最新檢查點之後（issue 001499）

`deriveStateAt` 原本寫成對任意目標 frontier 找不晚於它的最近檢查點再 replay；程式實際上只以最新檢查點為基底，
目標不在其後時退回從 genesis replay。兩者在一般節點上都需要已可被本機淘汰的 entry。改為：目標的 head 集合恰為
某個檢查點的 `log_head_cids` 時回傳該檢查點自己的 derived_state（驗 CID 與 canonical bytes，不 replay）；其餘只
支援最新檢查點之後的 frontier；已有檢查點時不退回 genesis replay，兩個較舊檢查點之間的目標回 null。自行定稿的
節點把手上已驗過的 signer set、覆核時重算出的 derived_state 與新成形的 cold partition 寫入本機並 pin，定稿的
步驟順序不變。[程式架構/ledger.md](../程式架構/ledger.md)、
[程式架構/ledger-checkpoint.md](../程式架構/ledger-checkpoint.md)、
[程式架構/interfaces.md](../程式架構/interfaces.md)、[資料系統.md](../資料系統.md) 同步。

> 決策檔：[D-20261123-05](../decisions/D-20261123-05-deriveStateAt的目標限於檢查點本身與最新檢查點之後.md)

### 2026-11-24 ─ 本機 prepare 一律不產生 refs（issue 001528）

本機 prepare 原本只在已有 checkpoint boundary 時把 `refs` 固定為空；尚無 boundary 時沿用 OrbitDB 的取法另取 `refs`。
無邊界時兩個 head 可能使本機寫入被自己的連結檢查拒絕。`refs` 不決定完整性，remote join 也不跟隨它，改為不分有無
boundary 一律固定為空陣列，`next` 仍為當下全部 heads。收件規則不變：遠端條目的 `refs` 仍驗 canonical CID、禁止
self/duplicate 並受數量上限限制。[程式架構/ledger.md](../程式架構/ledger.md) 同步。

### 2026-11-24 ─ 檢查點採納與覆核先驗簽後重算（issue 001514）

遠端 checkpoint 採納在 `full-refold` 模式下原本先以 checkpoint 自報的 heads 重算候選 derived state，之後才驗
proposer、signer set、quorum 與簽章集；`reviewAndSign` 也把重算排在 signer set、quorum 與節流檢查之前。改為兩者
都先做不依賴重算的檢查，全部通過才重算；簽章集等無效的公告不重算，且以 checkpoint CID 記入採納佇列的 negative
cache（signer set 由 checkpoint 記錄的 `previous_checkpoint_cid` 決定、簽章集包含在 CID 內，同一 CID 判定不變）。
heads 不在本機的假 checkpoint 因此直接拒絕，不再進入重試。`finalizeCheckpoint` 原本就先驗簽、不重算，順序不變。
[程式架構/ledger-checkpoint.md](../程式架構/ledger-checkpoint.md)、[程式參數/protocol.md](../程式參數/protocol.md) 同步。

### 2026-11-24 ─ 定稿或採納後的重建失敗進入 ingest recovery（issue 001526）

checkpoint 定稿後的重建失敗原本被吞掉：定稿回成功、復原狀態維持 idle、不排重試，節點繼續提供檢查點之前的
狀態；採納後的重建失敗則讓該次採納回到重試，下一輪因 latest 已是該 checkpoint 直接視為已採納，同樣不再重建。
改為兩者的重建各自在一個 state queue 工作內完成，失敗時在該工作內標記 ingest failure（業務讀寫 fail-closed），再依退避表排重試；
定稿與採納的結果不變。最新檢查點的狀態塊取不到時 `open` 的行為不在本次範圍。
[程式架構/ledger-checkpoint.md](../程式架構/ledger-checkpoint.md) 同步。

### 2026-11-24 ─ 條目儲存讀取失敗不刪底層、開庫記帳中斷重試一次後拒開（issue 001531）

有界條目儲存的讀取原本在底層讀取失敗或 quota 檢查失敗、且該 block 尚未記帳時，把它從底層刪除；條目只經寫入進入
專屬 store，未記帳不代表剛取得，開庫記帳中斷後讀到尚未列舉的既有條目、或讀取未命中與同一 block 的寫入交錯時，
都會刪掉條目，包括未被 checkpoint 涵蓋者。改為讀取失敗一律只拋錯、不刪除被讀取的 block；淘汰仍只依 quota eviction
規則（只淘汰已被涵蓋者）。開庫記帳（列舉讀取失敗、單塊過大、超過 byte／count 上限）原本中斷後仍開庫成功、之後
寫入全拒；依使用者裁決改為自動重試一次列舉，仍中斷即開庫失敗，拋出固定 code 與中斷原因的錯誤供上層辨識。列舉
回來的 CID 無法解析屬資料損毀，不重試，立即以同一 code、原因 invalid-key 開庫失敗。清空本機帳本並重新同步的介面
入口另由 issue 001527 處理。
[程式架構/ledger.md](../程式架構/ledger.md) 同步。
