### 2026-07-25 ─ checkpoint signer rotation 與 pinning 完整接線 review

> 決策檔：[D-20260725-03](../decisions/D-20260725-03-checkpoint前代authority與pinning切換完成.md)

- 完整 review 揪出本地 checkpoint 三法與 `full-refold` 會誤讀本代 frontier 折疊後的 signer set，使 signer rotation 形成自我授權（新成員可授權納入自己的事件）；改為 `proposeCheckpoint`／覆核／finalize／`full-refold`／`quorum-follow` 一律以**前一個已採納 checkpoint state** 的 signer set 驗證本代，第一個 checkpoint 讀 genesis。
- 本代 derived state 內的新 signer set 只授權下一個 checkpoint、不得回頭授權本代，與 `ConfigUpdateEvent` 的 `prevEpoch` 治理信任邊界對齊。
- pinning 啟動時把固定排序的 `GOVERNANCE_SIGNERS` 寫入 genesis、runtime 明確切換為 `quorum-follow`；完成 re-vendor 與「來源端包含 pinning replica 未知 reducer」的領域事件窗 E2E，解除 [D-20260721-01](../decisions/D-20260721-01-pinning-quorum-follow.md) 記錄的純 core 過渡限制。

### 2026-07-25 ─ 正式上線、本機離線與連線測試標準確認

> 決策檔：[D-20260725-04](../decisions/D-20260725-04-正式build可選runtime測試策略.md)

- 同一份正式 build 以不持久化的 URL query 明示啟動策略：`?runtime=local` 強制不啟動 network assembly、只建立 storage-only `local-ready`；`?runtime=network` 要求 network assembly 成功，失敗時登入嘗試 fail-closed，不自動假裝 online 也不降級成測試成功。
- 省略 query 或 `?runtime=auto` 是正式預設，連線失敗依既有能力模型安全降級 `local-ready`；未知值、重複的 `runtime` 參數與內部 policy 名稱一律視為 `auto`。
- runtime query 只控制本次啟動，不寫入玩家設定、IndexedDB 或其他持久資料，也不得改變 [D-20260716-01](../decisions/D-20260716-01-連線狀態機離線能力.md) 的能力閘；E2E 自此不必靠瀏覽器網路攔截與連線時序賽跑，避免「瀏覽器已連上才斷網」的競態假陰性。

### 2026-07-25 ─ graphify-out 跨 repo 關聯與 Prettier 排除複核
