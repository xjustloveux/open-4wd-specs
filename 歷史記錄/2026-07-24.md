### 2026-07-24 ─ 部署檢核、Pinning HTTP v2、Bootstrap／Relay 信任邊界收口

> 決策檔：[D-20260724-01](../decisions/D-20260724-01-signaling-v2部署拓撲.md)

正式部署欄位改由共享向量同時驗證 browser runtime 與 release script；`relayNodes` 與
unauthenticated bootstrap 清單完全分離。PinningProvider v2 補齊 SignedPayload、64 KiB
上限、timeout、嚴格 URL／CID／JSON 驗證與 reactive availability；pinning server 新增
fail-closed CORS allowlist。Bootstrap loader 加入 5 秒、64 KiB、256 行、64 筆與 multiaddr
界線。Circuit Relay 改為每個 libp2p generation 單一 listener 重用；直接連線全失或
15 秒冷啟動觀察窗仍為零連線時才嘗試明示 relay，且嘗試期間 direct 恢復不會被舊失敗
結果誤判。官方 signaling 現況定為 Cloudflare Worker＋SQLite-backed Durable Objects，
Node adapter 保留給公版自架者；pinning k8s 的 RWO 單副本更新策略同步固定為 `Recreate`。

同日 signaling 正式升為 scoped signed v2：移除全域 `lobby` 與「整場只選一個 provider」
假設，每個 `room:<code>`／`match:<digest>` 建立獨立 session；WebSocket 與 GossipSub
共用 canonical DAG-CBOR SignedPayload envelope、nonce replay guard 與 closed SDP／ICE
DTO。client 同時保留單一 active WSS 與 Gossip fallback，依 remote 最近有效入站 transport
回覆並跨 transport 去重；官方 WSS 故障或免費額度耗盡時有限次降級，不讓多人功能整體
失效。社群 signaling endpoint 只能由玩家明確加入，不建立自動信任陌生 operator 的公開
目錄。Worker front router 只做 admission，room／match 各自落 SQLite-backed Durable
Object，Hibernation、TTL、bounded nonce／token bucket 與不可逆 IP bucket 共同限制資源；
公版 Node 與 Worker adapter 通過同一 conformance vectors，公版 CI 只驗證與 dry-run。

官方部署拓撲同步定案：`open-4wd-signaling`、`open-4wd-pinning` 都是零 secrets、永不直接
部署的 public templates；官方分別從私有 `open-4wd-signaling-deploy` 與
`open-4wd-pinning-deploy` 跟版。官方 signaling 使用 Cloudflare，pinning／bootstrap 與
TURN 使用各自適合的部署面，避免全部落在同一故障域；穩定名稱固定為
`open4wd.org`、`signal.open4wd.org`、`pin.open4wd.org`、`bootstrap.open4wd.org` 與
`turn.open4wd.org`，`.com` 只做 HTTP 301。明確延後：實際私有 repo／官方部署、中央
`/match` rendezvous、Vercel／Deno adapter、TURN 多節點 HA、真實 ledger／signer／
bootstrap／legal 值，以及本機測試前的主 README；pinning `quorum-follow` 仍是已核准
目標，現行 runtime 維持 `full-refold`，待主 repo 模式落地、re-vendor 與領域事件窗
E2E 後再切換。
