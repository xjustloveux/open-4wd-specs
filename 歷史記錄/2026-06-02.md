## 重大重構里程碑

### 2026-06-02 ─ 移除冷啟動禮，改「首次上鏈負資產」

> 決策檔：[D-20260602-01](../decisions/D-20260602-01-首次上鏈負資產.md)

**動機**：經濟系統審視 Q1。初期公版 GLB 僅堪用、急需會做 GLB 的創作者；以「首次上鏈允許賒帳」取代鑄幣式冷啟動禮，零鑄幣、自我設限、淨補貼更低且自償。

| 項 | 變動 | 位置 |
|---|---|---|
| 移除冷啟動禮 | 刪 `OnboardingMintEvent` + `config.onboarding.amount_minor`；補助型鑄幣歸零（框架保留待節日活動回填）| 經濟 §3 / §4 / §10、資料系統 §3 事件表 + §4 DerivedState |
| 首次上鏈負資產 | 每 PeerId **一生一次**，上鏈（`UgcUploadEvent` / `UgcForkEvent` 燒費）餘額不足可入負；**不鑄幣**、債務天然封頂於該次上鏈費（≤ 500）；race-prize/royalty 自動還債 | 經濟 §9 / §10（含 §10.1 applyEvent 共識邏輯）/ §11、玩家整體旅程 §1/§2/§3/§6 |
| 省掉 DEBT_LIMIT 參數 | 「無上限 + 僅限一次 + 限縮上鏈」自我設限 → 不需獨立債務上限常數；債務相關治理旋鈕 = 0；程式參數表本就無 onboarding 參數（僅 經濟系統 §10 持有），故不動 | 經濟 §10 |
| 限縮在上鏈 | 只有上鏈能入負；擴車位（1000）、UGC 贊助等其他消費一律餘額 ≥ 0 | 經濟 §9 / §10 |

> **教學與經濟解耦（本次定案）**：「互動式 Onboarding（玩家整體旅程 §5）與經濟系統無關」——負資產靠「每 PeerId 一次」自我防 Sybil，不依賴 §5 gate，故本次未動 §5。§5 教學的詳細操作流程 / 內容後續另議；其指向的斷掉引用 `專案企劃書.md §E`（檔案不存在）一併待後續清理。

### 2026-06-02 ─ 斷線結算經濟規則（forfeit + finisherCount + <3 經濟 void）

> 決策檔：[D-20260602-02](../decisions/D-20260602-02-斷線結算finisherCount.md)

**動機**：經濟系統逐題審視 Q2。確立斷線 / 棄賽者的經濟處理，並堵「開房後全體斷線刷幣 / 刷 royalty」漏洞。冷啟動禮（Q1）仍另案討論中、尚未動工。

| 項 | 變動 | 位置 |
|---|---|---|
| playerCount → finisherCount | 比賽獎金公式玩家數重定義為**完賽人數**（非開賽人數）；變數 `playerCount` 全改 `finisherCount` | 經濟 §4 / §6、算式表 §13 |
| 斷線 / 棄賽 forfeit | 異常斷線者**與主動棄賽者**皆 forfeit：不計入 finisherCount、不發任何獎金；名次仍列最後供記錄 / TrueSkill / 信譽。先前 §12.4 兩者皆「視為最後名次完賽（領末位獎）」與 forfeit 牴觸，一併翻正 | 經濟 §6.2（新增）、比賽進行 §12.4 |
| finisherCount < 3 → 經濟 void | 完賽不足 3 人：`racePrizes` / `royalties` 全空（含三層分潤），但 RaceResultEvent 仍寫完整名次、TrueSkill / 信譽 / raceRecords 照常；空 settlement 仍走 ⌊N/2⌋+1 簽章 | 經濟 §6.2 / §7、算式表 §13、比賽結算 §12 |

> Q2③（單一使用者短時間頻繁斷線才扣信譽，非每次）**暫緩**：與現行「異常斷線每次 −5」+ `FREQUENT_DISCONNECT_THRESHOLD=5` 衝突，待信譽系統審查時一併 reconcile。
