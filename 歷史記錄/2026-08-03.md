## 重大重構里程碑

### 2026-08-03 ─ 持久儲存拒絕保留既有 UGC 偏好（issue 000152）

> 決策檔：[D-20260803-01](../decisions/D-20260803-01-持久儲存拒絕保留既有UGC偏好.md)

窄幅修正 D-20260802-13 的 persistence-denial 語意：`standard`／`generous` 的 persistent storage
請求被拒、失敗或 API 不可用時，只拒絕本次 requested mutation，保留請求前的 sanitized saved
level。先前為 `off` 就維持 `off` 並顯示拒絕 feedback；既有非 `off` 偏好在 persistence 未確認時
仍顯示原 level，但額外 retention 休眠且狀態為 `storage-not-persistent`。設定 action 不啟動網路、
身分、Ledger 或 storage authority；D-20260802-14 的 authority lifetime 與所有 storage 契約不變。

### 2026-08-03 ─ UGC GLB 改用 raw CID（issue 000163）

> 決策檔：[D-20260803-02](../decisions/D-20260803-02-UGC-GLB使用raw-CID.md)

確認既有上鏈管線把 GLB 原始 bytes 交給固定產生 dag-cbor CID 的 Ledger block writer，造成
multicodec 宣告與實際內容不符。UGC GLB 改用 `CIDv1(raw, sha2-256)`；checkpoint、
DerivedState、cold partition 與 signer set 等 canonical Ledger blocks 維持 dag-cbor。
讀取依請求 CID codec 重算 digest。因尚無正式 UGC，不建立 alias、雙讀或 migration。

### 2026-08-03 ─ Pinning 無官方節點，開發期 baseline 重設為 v1（issue 000164）

> 決策檔：[D-20260803-03](../decisions/D-20260803-03-Pinning無官方節點與開發期baseline-v1.md)

主 repo 移除預設／官方 pinning 清單與 `pinningUrls` deployment 值；玩家自行設定
`community`／`self-hosted` 節點，公版 pinning repo 只提供任何維運者可用的實作、image 與
部署模板。`GET /provider` 將 UGC read/write、legal notice、counter-notice、transparency 與
指定代理人登記分開聲明，DMCA 關閉不影響 UGC。Client 永不推導安全港資格。

2026-07-24 被稱為 `PinningProvider v2` 的內容只是第二輪內部強化；因仍無公開契約或相容
對象，完整能力直接成為唯一初始 `PinningProvider v1`，不建立 v2／v3、dual-read、migration
或 compatibility shim。

### 2026-08-03 ─ Provider-scoped DMCA 與私有簽章收件匣（issue 000165）

> 決策檔：[D-20260803-04](../decisions/D-20260803-04-Provider-scoped-DMCA與私有簽章收件匣.md)

Notice 完成 email 確認後，各 provider 保存自身 pin metadata 的可信 uploader PeerId，自動
unpin 並停止自己的供應；反通知轉寄原通知人、等待 14 個工作日，沒有人工驗核的法院行動
hold 就由 sweep 解除法律阻擋。Client 只查玩家自己設定的 provider，使用 requester 與 provider
雙向簽章的最小 inbox 通知原上傳 PeerId，不建立官方或全域 DMCA 清單。

案件法律狀態與 bytes 可用性分離：恢復時 exact bytes 尚在才 re-pin，否則記
`restored_after_counter + missing` 等待一般 exact-CID 補件。公版不替營運者登記指定代理人
或主張安全港，DMCA 能力 disabled 亦不連動 UGC read/write。本契約是唯一初始介面，沒有
v2／v3、migration 或相容分支。

### 2026-08-03 ─ UGC CAR 保存與 exact-root 本機補回（issue 000166）

> 決策檔：[D-20260803-05](../decisions/D-20260803-05-UGC-CAR保存與exact-root本機補回.md)

作品詳情可下載標準 CAR v1 保存包，UGC 瀏覽頁可匯入並精確補回原 CID 到本機 Helia。
目前格式固定為一個 `CIDv1(raw, sha2-256)` root 與一個 GLB block；驗證 root、block 數、
codec、大小與 digest 後才寫入唯一 storage authority。補回不是重新上傳，不建立新作品、
不改作者、不收費、不進入相似度或 pinning 流程，成功後只按一般 LRU 自然淘汰。專案尚未
發布，不提供 v2／v3、舊格式雙讀、alias 或 migration。

### 2026-08-03 ─ Runtime provider 全面社群化與專案權威分界（issue 000169）
<!-- homepage-milestone importance=5 -->

> 決策檔：[D-20260803-06](../decisions/D-20260803-06-runtime-provider全面社群化.md)

Open4WD 只維持單一、公開且由專案規格管理的 Ledger genesis／治理 signer set 信任根；
runtime 服務不因主專案維護、網域、registry 列名或 release check 而取得官方地位。Pinning、
signaling、bootstrap、relay、ICE／TURN、monitoring、gateway 與 DMCA 部署均由各自 operator
負責，玩家可手動選擇、自架或接受單次 session route。

主 repo 僅發布不含背書的技術 registry 與 client contract；registry 可為空，列名只表示上次
檢核時技術上可發現，不授予信任、寫入權或法遵資格。維護者若使用 `*.open4wd.org` 營運服務，
也只是遵守相同契約的一般社群 provider，可隨時關閉且不得成為發版或遊戲可用性的依賴。
