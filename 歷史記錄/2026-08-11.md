## 經濟正確性修復

### 2026-08-11 ─ Royalty 去重窗改以實際發放時間為錨（issue 000316）

修正同 `(cid, player)` 的 24 小時去重窗：只有 `MatchResultEvent` 實際鑄出該 UGC 的 royalty 時才更新錨點；窗內持續使用仍累加 `totalUses`、`uniqueUsers` 與單調的 `lastUsedAt`，但不再把下一次發放無限往後推。

Derived state 欄位由語意含糊的 `recentUsers` 正名為 `lastRoyaltyAtByPlayer`，checkpoint wire shape 同步更新。`RoyaltyShare` 新增已多簽的 `triggerPlayer`，讓 fold 能區分同場仍在窗內與已到期的玩家，只更新真正觸發發放的 `(sourceCid, triggerPlayer)`，不從作者收款人或同場其他玩家近似推算。新增每 8 小時持續使用的迴歸：第 8／16／24 小時不重複發放，第 25 小時因已超過首次實際發放 24 小時而可再次鑄出。

## 場地物理正確性修復

### 2026-08-11 ─ fixed 跑道改以折線線段投影判定中心線（issue 000327）

修正 `nearestOnRoute` 把「到最近預採樣點的距離」誤當成「到 spline 中心線的距離」：現在逐條預採樣折線做夾限投影，並在投影位置連續插值 half-width、tangent 與 up。舊行為的誤差隨 RoutePoint 間距成長，100m 直線即使車正在中心線上也可能量得約 4.15m 偏離，錯誤觸發 b-soft 減速與 teleport；修正後只保留 spline 與其預採樣折線本身的近似誤差。

新增長直線最大採樣間隙迴歸，鎖住中心線距離、寬度／up 插值與回到走廊即解除減速三項語意。相同距離固定保留較前線段，退化線段採固定 fallback，維持共識決定性。

## 贊助共識守門修復

### 2026-08-11 ─ UGC 贊助政策由 builder 下沉至 live 與 fold（issue 000317）

將 `sponsorship.min_amount_minor`、builtin、仲裁黑名單、target record 存在與禁止自己贊助自己五項規則抽成 `sponsorPolicyFailure` 純函式，由 UX builder、live receive validator 與 deterministic fold reducer 共用。手工簽署事件不再能繞過官方 UI，以低於治理下限的金額或無效 target 污染 top-100 贊助榜。

stateless schema 維持只驗 exact shape、canonical CID、付款人與簽署者一致及簽章；需要 DerivedState 的規則不放進 admission，避免同步進度造成分歧。live 對未知 CID 採 defer 等待鏡像同步，其餘政策違規 reject；fold 對所有違規 no-op，保留歷史 append 的最後決定性防線。

## 結算收件資源界限修復

### 2026-08-11 ─ Settlement 重算快取改為有界 LRU（issue 000314）

修正 `SettlementRecomputeGate` 對每組 `baseLogHeadCids` 永久保留完整 `DerivedState` 與失敗嘗試計數，導致長時間正常比賽也會無界成長。成功 state 與 attempts 現在共用單一 512-entry LRU，命中會刷新順位，逐出時同步清除兩者；成功暖身後立即清除不再需要的 attempt 計數。

同時把未完成的非同步 `deriveStateAt` 限制為最多 8 筆。滿載時仍回 `base-not-synced`，下一次收到或重審相同事件時即可在空位釋出後接續，不把暫時資源壓力誤判成永久拒收。每個仍受追蹤的 frontier 維持最多 3 次暖身；所有限制只屬 live admission 資源管理，不改事件內容、settlement 算式或 deterministic fold。

## Canonical PhysicsManifest 與一次性 Admission

### 2026-08-11 ─ Canonical PhysicsManifest 與一次性 Admission receipt（issue 000329）

將正式賽物理權威由 race runtime 直接讀取 GLB root／node extras，收斂為版本化 Canonical
`PhysicsManifest`。canonical finalizer 由實際幾何、材質、合法 empty 與已驗證作者宣告建立完整
manifest，嵌入 canonical GLB 並寫入 version／digest；UGC event 只保存 version／digest 參照。

首次看見 CID 時，content admission 在有界 Worker 內忽略 embedded manifest，從解碼後幾何與
作者宣告獨立重建並跑完整規則；digest、PhysicsFingerprint 或 event reference 任一不一致即拒收，

`AdmittedAsset`，不解析 raw extras、不跑 Wave A/B，也沒有缺欄 fallback。

開發期 asset schema 升為 `open4wd_version=2`，全部 27 個 builtin 由半成品來源協調正規化、
重烘 manifest 並同步 SHA／CID／provenance；不保留 v1 相容層。最大出貨零件、場地、27 資產
批次與 1,000 次 receipt hit 均加入效能 gate，底盤 mount 同時鎖為固定 18 個且恰有一個
`Mount_Weapon`。

## 逐 Region 接觸耗散輪胎磨耗

### 2026-08-11 ─ 極速巡航與滑行輪胎不磨耗（issue 000324）

輪胎 fatigue 不再以 `driveImpulseNs > 0` 與全車重量近似啟動，改由本幀 canonical
solid contact 計算 rolling impulse × rolling speed 與 tangential impulse × slip speed；slip 以
獨立倍率放大。因此極速巡航、無驅動滑行與下坡仍會耗胎，無 solid contact 及真正
靜止則為零。rolling 只按實際施加且 stop-clamped 的 impulse 記帳，避免低速停止時多算。

壽命分母改為每個 tire material region 的體積 × ultimate strength × synthetic 容量係數，
輪殼等非胎面區不會擴充實際耗胎容量。溫度以相對環境至熱限的比例 `r` 套
`1 + 2r²` 有界放大。PhysicsManifest 與唯一資產 marker 同步升 v7，27 個半成品
builtin 只用於合約驗證與 synthetic 初值，不視為最終平衡基準。

> 決策檔：[D-20260811-10](../decisions/D-20260811-10-逐Region接觸耗散輪胎磨耗.md)

合法組合由 runtime 的有限值 guard、clamp、budget 與決定性退化承擔。

材質效果改以實際 runtime consumer 定義：solid 接觸才使用 friction／restitution，輪組與 solid
surface 才使用 rolling resistance；地表／entity 是固定溫度熱庫，不建立動態地面熱場。fluid
維持 sensor＋deploy behavior，sticky 衰減不擴張為 3D viscosity、浮力或一般流體阻力。未來新增
能力必須同時補 runtime、測試與規格，不能只改材質參數就宣稱生效。

> 決策檔：[D-20260811-14](../decisions/D-20260811-14-材質Capability與介面嚴外形寬.md)

## 專案生命週期與首次公開發布鏈

### 2026-08-11 ─ 專案生命週期與首次公開發布鏈定案
<!-- homepage-milestone importance=5 -->

將 repo visibility、candidate maturity、runtime phase 與 live operating mode 拆成四條獨立軸；
正式相容義務由 `runtime_phase=live` 決定，不再以任一周邊 repo 是否公開推測。美術、正式 GLB、
驗證與 playtest 改為可交錯迭代，透過 Asset-ready 與 Pre-launch baseline 兩道 gate 收斂到同一
release subject，內部候選不挪用 public builtin 版本號。

首次公開鏈固定為 public specs＋`docs.open4wd.org` → main source baseline → pinning → signaling →

→ `open4wd.org` activation → workflow public。Docs 可索引並供閱讀、介紹與教學，但不是遊戲
runtime，不觸發 live。Main source baseline 與加入正式 Ledger 值後的 release SHA 明確分名；若
vendored path 在兩者之間改變，周邊同步與 provenance 必須重跑。

Main repo 成功轉 public 即不可逆進入 live。後續普通 rollback、參數回設、derive 重算或鏈重生都
維持 live，只依正常／緊急作業與既有版本、checkpoint、治理程序處理。
