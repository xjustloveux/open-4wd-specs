# 比賽進行

> **本檔角色**：從等待房鎖定資料的 preloading 二次驗證、GO 前 race-ready 屏障到完賽 / 超時的所有同步機制。
> 結算流程見 [比賽結算.md](比賽結算.md)；演算法見 [../算式表.md](../算式表.md)。

## 1. 鎖定裝備的二次驗證與參與證明（LoadoutSubmission）

等待房的 `ReadyDeclaration` 已經是最終選車，並已收進不可變的 `LockedStartPackage`。`preloading` 狀態不再允許換車；仍在線的 survivor 在固定時間內重送 matchId-bound `LoadoutSubmission`，用途是取得 ledger 參與證明並對鎖定資料作第二道驗證。倒數中已確認的 `preStartDisconnects` 不建立 race transport、不要求提交，也不提供本場重連；他們仍保留在 original roster、matchId 與原起跑格。提交與 survivor roster 交叉核對完成後才建立本回合 world／network／presentation；GO 倒數與模擬 frame pump仍須再通過 [§1.7](#17-go-前-race-ready-屏障)。

### 1.1 提交時間窗

| 階段 | 時長 | 行為 |
|---|---|---|
| 等待提交 | `LOADOUT_SUBMIT_WINDOW_SEC`（60 秒）| 收集 survivor participants 的 LoadoutSubmission；窗內收件即驗，無獨立互驗窗 |
| 完成提交階段 | — | 收到且精確符合 LockedStartPackage → 進 survivor roster 交叉核對；未提交者列為 disconnect，仍須滿足 original roster 的至少 2 人嚴格多數 |

提交窗以注入的單調時鐘記錄絕對 deadline；`setTimeout` 只負責喚醒並在 callback 時重算剩餘時間，不能把背景分頁被瀏覽器夾長的 timer 當成協議時鐘。回到前景時立即重評 deadline；尚未到期但 2 秒重送已逾期，只補送目前提交一次並從當下排下一次，不追補成 burst。

### 1.3 驗證項

| 場地相容性 | 車輛 AABB.x + `NARROWEST_PATH_MARGIN_M`（0.05）≤ `auto_narrowest_path_m`（場地）— 警告但不阻擋 |

### 1.4 不上鏈

`LoadoutSubmission` **不單獨寫進 ledger**，賽後 loadout 與其 matchId-bound 簽章分別納入 `MatchResultEvent.loadouts` 與 `loadoutSignatures` 一併儲存（省 ledger 空間 + 賽後可審計）。**簽章 ＝ 參與證明**：收件 ⓪-loadout 驗其有效性、applier 只罰 ／ 只評有 loadout 者——擋憑空自造一場塞任意玩家 `disconnects` 投毒信譽 ／ 灌斷線（[../程式架構/ledger-admission.md §1](../程式架構/ledger-admission.md)）；absent（未交 loadout＝ 無承諾）者不受斷線罰。

### 1.5 重連時的 loadout 處理

本節只適用 GO 後的中途斷線。倒數中列入 `preStartDisconnects` 者本場不提供重連；GO 後中途斷線 < 15 秒可重連的玩家**沿用原 loadout**（避免重連時偷換）。重連時 peer 端比對 `loadoutHash`：

```typescript
if (reconnectingPeer.loadoutHash !== originalSubmission.loadoutHash) {
  // 拒絕重連，視為新連線（重新加入需新一場比賽）
}
```

### 1.6 名單交叉核對（開賽前共識輪）

loadout 交換各端的提交窗**獨立定案**——名單剪刀差（某端視 X 在場、他端視 X 逾時 disconnect）若不擋下，開賽後各端模擬的車數不同 ＝ 決定性立即發散。交換定案後、世界構建前：

1. **各端算 survivor 名單指紋**——rosterHash = sha256(sorted `${peerId}:${loadoutHash}` 行 join '\n')；matchId、grid proof 與 original roster 不重算。
2. **廣播 roster-confirm**（含週期重送；首見對端指紋 ＝ 回打自己的——對端可能漏收首發）。
3. **全員指紋一致 → 進 racing**；任一不一致或逾時未齊 → fail-closed 全員棄賽（重新配對）。

寄件者身分 ＝ 傳輸層連線歸屬認證（同 control 訊息慣例）。已知取捨：房內任一成員可蓄意送錯指紋炸掉開賽（等價於它拒不提交 loadout 的擾亂能力、不放大）。

### 1.7 GO 前 race-ready 屏障

survivor roster 共識完成後，每一回合都建立新的 `RaceReadyCoordinator`。屏障只計已通過上述交叉核對的 survivor participants；original roster 內的 `preStartDisconnects` 與 preloading 缺席者不送、不等，觀戰者也不能阻塞 GO。首回合 GO 後的後續回合，等待集合另扣除已記入 `disconnects` 的斷線或離場者，以及前幾回合的流內離場者：他們送不出進度，已發生的 `peer-left` 也不會重播。訊息綁定 `matchId`、`roundIndex`、傳輸來源與 `sender`，非 survivor roster、錯場、錯回合或來源冒名一律丟棄。

```typescript
type RaceReadyMilestone = 'world-built' | 'network-ready' | 'presentation-ready';

interface RaceReadyMessage {
  type: 'race-ready';
  matchId: string;
  roundIndex: number;
  sender: PeerId;
  milestone: RaceReadyMilestone;
}
```

milestone 為有限、嚴格單調序列：

1. `world-built`：本回合物理 world 與所有車輛 rig 已建立。
2. `network-ready`：本回合 rollback network 已可用。
3. `presentation-ready`：場地資產、全 survivor roster 車資產皆成功完成，且 viewport 在完成後實際 render 至少一幀；proxy／失敗資產不得假冒完成。同賽道下一回合仍須重開 readiness 世代。

每端只接受高於既有 rank 的進度；重送或倒退不算進度、不得延長 stall 窗。最新本機 milestone 每 2 秒重送以容忍 control message 遺失。stall 與 resend 都保存單調時鐘絕對 deadline，timer callback 只重算／重排；回到前景時立即檢查 stall，若仍有效但 resend 已逾期則只補送一次。只有全 survivor roster 都達 `presentation-ready` 才進入開賽巡禮、countdown／frame pump 與 GO。

**開賽巡禮**（[D-20261113-03](../decisions/D-20261113-03-開賽巡禮依場地挑選鏡位.md)）：場地載入後，viewport 依場地資料（`RoutePoint_<n>` 路徑節點、路寬、是否環狀、場地包圍盒）規劃三個巡禮鏡位，鏡位只取決於場地資料、算一次後快取。每個地點由固定的候選相機位置中，挑出在場地範圍內、與注視點之間視線無遮擋、下方有場地且四周有最小淨空的一個；三個地點沿路徑弧長分散，最後一個在起點。RacePage 在 readiness barrier 期間循環播放這三個鏡位，不把巡禮放回 RoomPage。每一回合全員到齊後，各端在本地屏障完成時起算一段固定巡禮（`STARTUP_TOUR_SHOT_COUNT` × `STARTUP_TOUR_SHOT_MS`，三個鏡位各 2 秒共 6 秒），結束後才開始 countdown；固定巡禮不經網路訊息，各端誤差與既有 countdown 相同。場地更換時鏡位重新規劃。回合世界建好後，模擬端隨 `round-built` 送出一個尚未步進的初始呈現幀，車輛停在起跑格上，供巡禮與倒數期間顯示；它只供本機呈現，不進共識、快照、wire 與觀戰廣播，也不驅動賽中音效（[D-20261113-06](../decisions/D-20261113-06-開賽巡禮每回合進行並顯示車輛.md)）。物理把車生成在起跑格上方數公分，GO 之前呈現層把顯示高度放到貼地，GO 之後回到物理位姿。countdown 開始時 participant 的鏡頭切到跟車自己，GO 之後不再切換鏡頭。GO 之前 HUD 已顯示，計時為 0、技能鈕停用。之後由使用者控制，淘汰或完賽不自動切鏡。外部 spectator 初始為自由，不同步固定巡禮，GO 之前看不到車。場地沒有路徑節點時由包圍盒長軸取三個地點；某地點沒有合格候選時使用範圍內的鏡位並在播放時做即時避讓；場地未載入時維持局部車群導播。

**本回合場地的呈現**：viewport 回報 `presentation-ready` 時附上該場景是為哪個場地建的，RacePage 只把與本回合場地相符的回報轉交 RaceSession。session 發出本回合場地後、viewport 重建場景前，無場地的舊場景可能先完成首幀；那不是本回合的呈現，不得計入。參賽者首次開賽到本機 `presentation-ready`、開賽巡禮開始或倒數開始之前，RacePage 以載入遮罩蓋住 3D 場景：資產載入完成前 viewport 顯示的是無資產時的代理場地與占位車，不讓參賽者把它當成比賽場地；開賽失敗或賽事結束時遮罩收起，後續回合不再顯示。比賽場景建好後，會重建場景的只有三種變動：本回合場地更換、顯示效果品質、反鋸齒設定（更換 renderer 後補跑重建）；比賽頁內只會發生第一種，後兩者只能在設定頁更改。主題切換就地更新材質、場景 profile 與後處理，不重建場景（[../程式架構/themes.md §2.1](../程式架構/themes.md)）。鏡頭模式切換（倒數開始由巡禮切到跟車、使用者切換鏡頭、觀戰換目標）與其他設定寫入（比賽中調整跟車距離會寫回設定）都不得重建：重建會讓代理場地重新露出、場地與車輛重新載入。

**本機測試**：沒有 roster 屏障。RacePage 有 viewport，開賽時以開賽參數要求 RaceSession 在倒數前等本機 `presentation-ready`；等待上限為 `RACE_READY_STALL_TIMEOUT_MS`；就緒或逾時後先做固定巡禮再倒數與 GO：資產載入失敗時 viewport 留在代理場地，本機測試仍可進行。沒有 viewport 的宿主（內部模擬路由等）不提出要求、不等待，也不巡禮。

**取消語意**：取消只適用於首回合 GO 前。任一 survivor peer 在首回合 GO 前觸發 `peer-left`，或 `RACE_READY_STALL_TIMEOUT_MS`（30 秒）內沒有任何嚴格進度，立即取消屏障。此時不倒數、不 step、不產生 round／match settlement，也不記 forfeit、斷線或信譽變動。房主批次移除 missing 的非 host participant（host 永遠保留），房間回 `waiting`、清 `currentMatchId`、LockedStartPackage 作廢、全員 Ready 歸零並廣播單一新 snapshot；所有仍在線 participant 返回 `/room/:roomId`。其後須重新 Ready、驗證並自動倒數，以新 `startedAt` 推導新 id。

首回合 GO 後比賽已經開始，後續回合屏障期間收到的 `peer-left` 不取消屏障：只把該 peer 移出等待集合，其餘成員到齊即進 GO。續賽與否交給 partition guard 的嚴格多數規則（[§12.2](#122-異常斷線後處理)），離場者依 [§12.4](#124-graceful-leave-vs-異常斷線) 記 forfeit。前一回合流內離場者在下一回合自 frame 0 起即為退出；網路斷線者不列入起點退出，只記 forfeit（[../賽內機制.md §3.1](../賽內機制.md)）。

**後續回合停滯**：首回合 GO 後的回合若 `RACE_READY_STALL_TIMEOUT_MS` 內沒有任何嚴格進度，不取消屏障，改把尚未達 `presentation-ready` 的等待成員移出本回合，其餘成員視為到齊、照常倒數與 GO。被移出者比照 GO 後網路斷線處理：寫入結算 `disconnects`（forfeit），依 [§12.4](#124-graceful-leave-vs-異常斷線) 與 [../賽內機制.md §4](../賽內機制.md) 計名次與信譽，不通知模擬端，其車以斷線車規則留在模擬世界。

- 移除後若非 forfeit 的剩餘成員數低於 original active roster（`ranking ∪ disconnects` 去重）的 ⌊N/2⌋＋1，整場作廢：不開始該回合、不執行 settlement、不產生 `MatchResultEvent`，結果與 `partition-void` 相同（[§12.2](#122-異常斷線後處理)），不做部分結算。
- 本機自己未達 `presentation-ready` 而判定停滯時，走既有驅逐收攤：停模擬、送 control `leave` 並退出本場，不再參與後續回合。
- 各 peer 對已記為 forfeit 的成員，一律丟棄其本回合的輸入與 checksum 投票。
- 停滯判定使用各 peer 的本機單調時鐘，邊界情況下各端 `disconnects` 可能不同；此時結算候選核對拒簽，湊不到 ⌊N/2⌋＋1 簽章即依多簽未達門檻整場作廢，不會產生錯誤結算。

## 2. 高層概念

| 機制 | 目的 |
|---|---|
| 輸入延遲 D＋有界回滾 R | 單向延遲 ≤ D×T 不預測；更晚的 input 預測＋回滾 ≤ R 幀 |
| Fixed timestep 60Hz | 跨平台 deterministic；模擬在 Worker 內單執行緒執行 |
| Snapshot Checksum | 偵測 desync |
| 回合 Consensus Anchor | 終局尾窗唯一多簽證書 |

## 3. 每幀（16ms）

```mermaid
%%{init: {"theme":"base","themeVariables":{"fontSize":"14px","primaryTextColor":"#1f2937","lineColor":"#64748b"},"flowchart":{"curve":"basis"}}}%%
flowchart TD
    A(["玩家 input<br/>鍵盤／手把（主執行緒）"]) --> B["排程到 current＋D<br/>簽章並廣播"]
    B --> C{"模擬 Worker 收遠端 input<br/>預測 vs 實際"}
    C -->|"不符"| D["rollback ≤ R 幀<br/>載前緣快照・重 step 到當前"]
    C -->|"符合或尚未到"| E["推進一幀<br/>對齊幀與含預測幀才存快照"]
    D --> E
    E --> F["主執行緒渲染當前 state<br/>固定頻率插值平滑"]
    E --> G["已確定幀<br/>發出已確定記錄"]

    classDef local fill:#e8f3ec,stroke:#3f8f5f,stroke-width:1.4px,color:#173525;
    classDef consensus fill:#fdf3df,stroke:#c08a2d,stroke-width:1.4px,color:#3d2c0d;
    classDef ui fill:#efeafa,stroke:#7a5cb8,stroke-width:1.4px,color:#2b1d4d;
    class A,B local
    class C,D,E,G consensus
    class F ui
```

1. **玩家 input（鍵盤 / 手把）→ 主執行緒取樣**——在 local frame c 取樣到的技能事件排到 frame c＋D（`INPUT_DELAY_FRAMES`）才生效，以排程幀簽章並廣播到 mesh DataChannel；技能鈕只給「已受理」視覺回饋，不預演技能效果（[../賽內機制.md §2.1](../賽內機制.md)）。每回合 frame 0 到 D−1 是全員隱含空輸入幀。
2. **模擬 Worker 推進**——主執行緒把已驗簽的遠端 input 轉給模擬 Worker；遠端輸入尚未到達的幀以「延續 Hold、Event 不重放」預測。單向延遲 ≤ D×T 時輸入準時到達、不需預測。步進前只有對齊幀（每 8 幀）與含預測的幀存快照（前緣快照）。
3. **遲到 input 修正**——真值與預測不符 → 載入 ≤ 該幀的最近快照、用正確 input 重新 step 到當前幀，重播深度 ≤ R；早於 current − R 的 input 丟棄。
4. **已確定記錄**——幀的全部輸入成為真值後，依幀序發出已確定記錄，供 checksum、回合共識錨、觀戰 checkpoint 與回合終局使用（§4、§5、§13）。
5. **主執行緒渲染當前 state**（含 60Hz 插值平滑）與 HUD；模擬 Worker 的落後不凍結畫面。

執行緒配置、快照規則與已確定串流見 [../程式架構/network-sync.md §3–§5.1](../程式架構/network-sync.md)。

hash 演算法 ＝SHA-256（32 bytes）。checksum 幀步進時只記暫定 hash，回滾重播經過時覆寫；該幀已確定（受理窗外，或窗內每幀已收齊全 roster 真值）後才廣播，所以誠實 peer 的票必定基於同一組輸入（[../程式架構/network-sync.md §4](../程式架構/network-sync.md)）。

`SNAPSHOT_INTERVAL_FRAMES: 120`、`PEER_DESYNC_TOLERANCE_FRAMES: 30`（**等待容差窗**：某 peer 的 checksum 逾 30 frame 未到 → 該輪視同缺席、不阻塞多數決）。

## 5. 每回合終局 — 唯一 Consensus Anchor

每 120 frame 的 checksum 票只做 ephemeral desync 偵測。每回合終局在 bounded window 內建立至多一張寫入 ledger 的嚴格多數證書，公式與事件 schema 見 [../資料系統.md §6](../資料系統.md)。

```mermaid
%%{init: {"theme":"base","themeVariables":{"fontSize":"14px","primaryTextColor":"#1f2937","lineColor":"#64748b"},"flowchart":{"curve":"basis"}}}%%
flowchart TD
    A["穩定順序 proposer<br/>提出終局 tail 候選"] --> B{"其他 peer 驗本機保留／final<br/>checksum、roster、每回合未簽？"}
    B -->|"一致"| C["簽章背書並鎖定本回合"]
    B -->|"不一致／已簽"| D["拒簽"]
    C --> E{"湊到嚴格多數？"}
    E -->|"是"| F["廣播唯一完整證書"]
    F --> G["保留證書<br/>結算時 inline 進 MatchResult"]
    E -->|"否且 proposer 逾時"| H["下一位 deterministic fallback"]
    H -.->|"bounded window 到期"| I["該回合 roundAnchors[] = null<br/>整場禁止鑄幣"]

    classDef consensus fill:#fdf3df,stroke:#c08a2d,stroke-width:1.4px,color:#3d2c0d;
    classDef chain fill:#e7eefb,stroke:#3f6bb0,stroke-width:1.4px,color:#152848;
    classDef fail fill:#fae9e7,stroke:#b4544a,stroke-width:1.4px,color:#471d18;
    class A,B,C,D,E,H consensus
    class F,G chain
    class I fail
```

**步驟細目**：

1. proposer 依 original roster 的 PeerId code-unit 順序選出；逾時每 `CONSENSUS_ANCHOR_FALLBACK_SLOT_MS`（2000ms）換下一位。
2. 候選 frame 只能是 rollback finality 之外最後 120-frame 對齊邊界或其前一個邊界；本機只記已確定記錄所附的 120-frame 對齊 hash（預測中的狀態不入錨），catch-up 重置時補記載入幀的錨。signer 必須仍保留該幀、checksum 相同、`presentPeers` 與本機在場名單一致，且本回合尚未簽過。終局幀與 checksum 都取自已確定狀態；流內離場已含在該狀態中，不另比對離場訊息的到達時序。
3. 湊到 `floor(presentPeers.length/2)+1` 個不同 signer 後廣播完成證書；結算時將完整證書 inline 放入 `MatchResultEvent.roundAnchors[roundIndex]`。證書簽 `gridContextDigest + gridSeed` 綁定外層唯一完整 `gridProof`，不重複攜帶大型 commitment/reveal payload；未達 quorum 填 `null`。
4. `CONSENSUS_ANCHOR_COLLECTION_TIMEOUT_MS`（12000ms）到期仍無 quorum → 對應 `roundAnchors[roundIndex]` 填 `null`；不得單簽 fallback，canonical fold 只能產生 `mintEligible=false`。

## 6. Desync 偵測與處理

```mermaid
%%{init: {"theme":"base","themeVariables":{"fontSize":"14px","primaryTextColor":"#1f2937","lineColor":"#64748b"},"flowchart":{"curve":"basis"}}}%%
flowchart TD
    A["checksum 廣播後等待窗收齊<br/>逾窗視同缺席"] --> B{"有嚴格多數 checksum？"}
    B -->|"有"| C["少數 peer 累積 desync strike<br/>一致時 strike 歸零"]
    B -->|"無"| X["全端結束整場<br/>consensus-invalid"]
    C --> D{"連續 strike 達上限？"}
    D -->|"是"| E["persistent-desync<br/>自報 leave・踢出計棄賽"]
    E --> F[("DesyncEvent 進 ledger<br/>被踢者自簽自報")]

    classDef consensus fill:#fdf3df,stroke:#c08a2d,stroke-width:1.4px,color:#3d2c0d;
    classDef chain fill:#e7eefb,stroke:#3f6bb0,stroke-width:1.4px,color:#152848;
    classDef fail fill:#fae9e7,stroke:#b4544a,stroke-width:1.4px,color:#471d18;
    class A,B,C,D consensus
    class E,X fail
    class F chain
```

**步驟細目**：

1. **Snapshot Checksum 廣播後，等待窗 PEER_DESYNC_TOLERANCE_FRAMES（30 frame ≈ 0.5s）收齊**——逾窗未到的 peer 該輪視同缺席、不阻塞多數決。
2. **只接受嚴格多數 checksum**。2–2、3–3、2–2–1 等平手無法辨認哪端是少數，所有端一致結束整場 `consensus-invalid`，不各自把自己或對手當成被驅逐者。
3. **有嚴格多數時，與多數派不一致的 peer → 累積 1 次 desync strike；一致時歸零**——不 rollback、不中斷比賽（決定性重播同一批 input 必得同一結果，治不了真分歧）。
4. **連續 strike ≥ DESYNC_STRIKE_LIMIT（3、防假陽性）→ persistent-desync**——該玩家自我驅逐：停模擬並送 control leave（reason `'desync'`），對端只記斷線（forfeit）、不影響回合終局 → 被踢出 race、計棄賽；DesyncEvent 進 ledger（被踢者自簽自報、含其觀測的 hash 票面）。

**持續落後不是 desync**：裝置或網路持續跟不上、嚴格過半且至少兩名遠端領先超過回滾窗 R 連續 `PERSISTENT_LAG_DEMOTE_FRAMES`（300 幀、5 秒）時，落後端自我驅逐，結束原因 `lag-evicted`——同樣停模擬、送 control leave 並退出回合（對端只記斷線〔forfeit〕，不影響回合終局），但**不自報 `DesyncEvent`、不計入 desync 統計**；兩人場永不觸發；catch-up 進行中暫停計數，probe 期間延後到 probe 失敗才驅逐。三人以上的單次卡頓讓嚴格多數遠端領先超過 D＋R 時，落後端自判輸入已越過他人受理窗：停送本機輸入與 checksum 票，直接走 catch-up 快照重同步（不受自動 catch-up 冷卻限制），成功後清除本機 desync strike，卡頓者多一次重同步停頓但不被驅逐；兩人場維持原行為，越窗卡頓仍可能因 checksum 分歧結束（[../程式架構/network-sync.md §7.5](../程式架構/network-sync.md)，[D-20261030-05](../decisions/D-20261030-05-越窗卡頓改走catch-up.md)）。結束畫面提示可回房以觀戰者身分觀看，不自動重新加入（[../程式架構/network-sync.md §7.3](../程式架構/network-sync.md)）。

`DesyncEvent` **不影響玩家信譽、純供開發者調查**（[../程式架構/ledger.md §9](../程式架構/ledger.md)；作弊由自動機制當場處置——持續 desync 踢出計棄賽即其代價，作弊非檢舉類型，[../信譽系統.md §5.1](../信譽系統.md)）。簽章 ＝ 被踢者單簽（無法強制他人為調查記錄簽章；事件無 state reducer、收件放行）——`signatures[]` 欄容多簽、他端自願附簽為開放項。

## 7. Anchor 衝突處理

同一 `(matchId, roundIndex)` 若收到兩張不同且各自完整有效的嚴格多數證書，代表 per-round sign-once equivocation 或 membership view 分裂。各端保存兩張原始證書與重疊 signer 至 `RaceAbortEvidenceEvent.anchorConflicts`，整場 `consensus-invalid`、禁止鑄幣；不採最長鏈、first-seen 或 checksum 字典序選邊，也不做 majority state overwrite。

### 12.1 Reconnect 流程


**步驟細目**：

1. **玩家斷線** → 其他 peer 啟動 ReconnectHandler（RECONNECT_TIMEOUT_MS: 15_000）；15 秒內持續嘗試 reconnect（500ms 輪詢）。
2. **重連成功** → 沿用原 loadout（比對 loadoutHash 防偷換，[§1.5](#15-重連時的-loadout-處理)）＋ 催定向 state catch-up（best-effort：嚴格多數遠端對同一已 final 對齊快照背書後，向一位 voter 發帶 requestId/target 的 sync-request → 同一 peer 關聯的 sync-response 帶快照 F 與 provider 的簽章輸入日誌 → 逐筆驗簽、原子 loadState；未請求 ／ 錯來源 ／ 超過 900 幀拒收；見 [../程式架構/network-sync.md §7.1](../程式架構/network-sync.md)）。
3. **追前緣後續賽**——恢復端載入 F、採用日誌，依牆鐘預算分多個 tick 追到夾限後的前緣，追趕結束後本機輸入自結束幀＋D 恢復排程（[../程式架構/network-sync.md §7.1](../程式架構/network-sync.md)）；之後的小幅落後由落後端快進回收，三人以上超過 D＋R 時改走 catch-up（[§7.5](../程式架構/network-sync.md)）；仍落後 ／ 無人應答 → 持續落後自我驅逐（§6）或後續 checksum 分歧走 desync 自我驅逐（≡ 異常斷線）。
4. **15 秒未重連** → 視為異常斷線。

### 12.2 異常斷線後處理

1. 15 秒後的 race-mesh `offline` 不代表 room-control／spectator-stream 離線；三平面以 `(peerId, plane, generation)` 各自裁定。
2. GO 後由固定 original active roster 的嚴格多數守門：本端可達數 `≥ floor(N/2)+1` 才移除失聯者並續賽；不足則 `partition-void`，不產生 MatchResult／信譽／TrueSkill。後續回合屏障停滯移出的成員（[§1.7](#17-go-前-race-ready-屏障)）同樣計入失聯，剩餘非 forfeit 成員不足門檻時整場作廢。
3. 可續賽側仍須由原 roster 嚴格多數對包含 `disconnects` 的完整 candidate 簽章；此簽章集即 removal certificate。3 人 2–1 可 2 簽；4 人 3–1 要 3 簽；4 人 2–2、2 人 1–1 均無法定稿。
4. 合法 removal 的玩家位置為最後完賽者之後（依斷線時間排序）；已交本場簽章 loadout 者信譽扣 −5（absent 不罰，見 [../信譽系統.md §2](../信譽系統.md)）。

### 12.4 Graceful Leave vs 異常斷線

| 類別 | 訊息 | 信譽影響 | 經濟結算 |
|---|---|---|---|
| Graceful Leave | GO 後 best-effort 上鏈本人單簽 `RaceLeaveEvent`；回合進行中先經已簽輸入流送 leave 並等 flush（有上限），再送 control `{ type: 'leave', reason: 'voluntary' }`（[../程式架構/network-sync.md §7.4](../程式架構/network-sync.md)）。該回合自 leave 生效幀起計退出（DNF，[../賽內機制.md §3.1](../賽內機制.md)）| 本人 `disconnectCounts +1`、`frequent-disconnect -5`；與同場 `MatchResultEvent.disconnects` 以 `(matchId, peerId)` 持久去重 | `RaceLeaveEvent` 本身不產生排名、TrueSkill 或經濟效果；若後續 MatchResult 達原 active roster 嚴格多數，才以 forfeit 記最後名次、不計 finisherCount、不發獎金（[經濟系統.md §6.2](../經濟系統.md)）|
| 異常斷線 | race-mesh 15 秒未重連；由原 active roster 嚴格多數納入 `MatchResultEvent.disconnects`。斷線車在模擬中照常以預測輸入行駛，不影響回合終局與名次分區；回合之間或 GO 前的主動離場、自我驅逐也走這一類 | `disconnectCounts +1`、`frequent-disconnect -5`；與同場 `RaceLeaveEvent` 共用去重鍵 | 合法 MatchResult 以 forfeit 記最後名次並累積影響 σ；無 quorum 則整場 fail-closed，不得由少數替第三人扣分 |

## 13. 回合結束觸發

| 觸發 | 處理 |
|---|---|
| 完成 `lap_count` 圈 | 玩家進入「已完賽」；其他人繼續 |
| chassis broken（`physicsRetired`）| 玩家自動切觀戰；battery／motor 失能不切觀戰 |
| 場上無未完賽存活車 | battery／motor 失能車進入最多 120 幀的回合級終局窗；全部低於速度門檻連續 15 幀可提前結束 |
| 玩家主動退出（流內 leave 生效）| 該車計為退出（DNF），不再阻擋回合結束；網路斷線不算退出（[§12.4](#124-graceful-leave-vs-異常斷線)）|
| 達房間設定的賽程時間上限（預設 600s、範圍 60–1800）| 強制結算依當前名次 |

以上觸發一律以**已確定幀**判定：預測輸入下的衝線、全員停車或時限不結束回合，終局延後到終局幀的全部輸入成為真值；終局幀、名次與致毀統計取自已確定記錄（[../賽內機制.md §3.1](../賽內機制.md)）。回滾超窗、不可恢復落後或 `lag-evicted` 時本機立即停止消費並視為本機終局，不再以後續記錄定稿回合。
